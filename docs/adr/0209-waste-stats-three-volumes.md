## Контекст

Вкладка «Вывоз мусора» → «Статистика» (ADR 0193) показывала по площадкам месяца один столбец
«Объём» — вывезенное по закрытиям плюс заказанное незакрытыми заявками, с подписью «в т. ч.
заказано», — и один столбец «Стоимость» того же устройства. Заказчик попросил вместо одного объёма
три: планируемый (все действительные заявки, включая новые), выполненный (выполненные и завершённые
заявки) и подтверждённый (выполненный объём, подтверждённый талонами), и связать с ними стоимость.

План прошёл две волны корректуры с перекрёстным судейством; в репозиторий он не переносится и после
исполнения не хранится, поэтому решения заказчика и определения величин записаны здесь дословно.

## Решения заказчика (опрос 25.09.2026)

| №   | Вопрос                               | Решение                                                                                                                                                                                            |
| --- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| З1  | Вёрстка                              | Три столбца объёма и ОДИН столбец стоимости: `Площадка · Заказано · Вывезено · По талонам · Стоимость`                                                                                             |
| З2  | Какая стоимость основная             | Крупно — стоимость вывезенного (суммы закрытий). Плановая и подтверждённая стоимость — подписями под ней: «план … ₽», «по талонам … ₽»                                                             |
| З3  | Плановый объём у закрытой заявки     | Заказанный объём (не вывезенный). Если заказанного нет (старые заявки) — вывезенный                                                                                                                |
| З4  | Подтверждённый объём при расхождении | Сумма объёма принятых талонов как есть (кроме простоя), БЕЗ ограничения вывезенным: может быть больше 100 % вывезенного                                                                            |
| З5  | Откат «Выполнена → В работе»         | По статусу, везде: такая заявка только в «Заказано». Правило меняется в слое атомов, значит и в книге Excel сводной аналитики                                                                      |
| З6  | Месяц заявки                         | Как было: один день отнесения на заявку — фактический день вывоза, при его отсутствии день доставки (МСК)                                                                                          |
| З7  | Подписи второй строкой               | Только «N заявок» под «Заказано». Подписи достоверности остаются всегда: «объём не прочитан у N талонов», «без цены … м³», прочерк вместо суммы без цены. «N без цены» под стоимостью не выводится |
| З8  | Названия                             | «Заказано», «Вывезено», «По талонам», «Стоимость»                                                                                                                                                  |
| З9  | Итог                                 | Строкой «Итого» внизу таблицы; полоса сводки сверху сокращается до «Площадок / Заявок / Вывозов»                                                                                                   |
| З10 | Справочник цен                       | Пустые цены на проде — ошибка данных, в задачу не входит                                                                                                                                           |
| З11 | Данные прода                         | Замера на проде не будет; вопросы по данным — прямым опросом. Ответ: возвраты «Выполнена → В работе» бывают изредка                                                                                |

| З13 | Окно выката                          | Определяется в конце волны реализации                                                                                                                                                              |

## Определения величин

Набор заявок месяца — тот же, что у загрузчика атомов: не удалённые, не отменённые, день отнесения
внутри месяца, область — площадки читателя, тип с фактом в кубах. «Статус-факт» —
`analyticsCountsAsFact`: «Выполнена» или «Завершена».

| Величина   | Заявки                      | Объём                                                                                                                                      | Деньги                                                                                                       |
| ---------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| Заказано   | весь набор, в любом статусе | заказанный: живые строки самосвалов (Σ объём × число машин); строк нет — объём заявки; и его нет — объём закрытия (З3); нет и закрытия — 0 | из того же источника, что объём: строки (если цена у всех), сумма заявки; при откате на закрытие — его сумма |
| Вывезено   | статус-факт                 | объём закрытия                                                                                                                             | сумма закрытия (законно пуста — «без цены»)                                                                  |
| По талонам | статус-факт                 | сумма объёма принятых талонов, кроме простоя                                                                                               | объём талонов × цена закрытия                                                                                |

## Решения

### Р1. «Заказано» — новые поля атома, и объём с деньгами берут одну ветвь

Атом вывоза получил `volumePlannedM3`, `moneyPlanned`, `volumePlannedUnpricedM3` и
`volumeFactUnpricedM3`. Прежний `volumeOrderedM3` для этого не годится: у выполненной заявки он
ноль и на вопрос «что заказали» не отвечает.

Сумма заявки — производная базы от её объёма (`amount` GENERATED), поэтому у старой заявки без
объёма пуста и сумма. Возьми объём у закрытия, а деньги у заявки — и кубы попали бы в «Заказано»
без своих рублей. Поэтому при откате на закрытие (З3) деньги берутся у того же закрытия, и условие
ветви у объёма и денег одно. Обоснование Р3 ADR 0193 — объём и деньги одной пары описывают один
набор заявок — сохраняется для каждой из трёх пар; отменено только сложение вывезенного с
заказанным в один столбец. Оценка книги (`moneyLow`) не меняется и из плана не выводится: у
заявки со статусом не-факт и заказанным объёмом они равны по построению, и db-тест держит это
равенство.

Строки самосвалов — состав техники прошлых закрытий (только чтение, перенесены в закрытия
миграцией 0056). У старых заявок со строками «Заказано» совпадает с вывезенным; новых таких заявок
не бывает.

### Р2. «Вывезено» определяет статус, а не закрытие — во всём слое атомов

Откат «Выполнена → В работе» закрытие сохраняет, чтобы повторное закрытие не спрашивало те же
цифры. До этого решения вывоз, объём и вес считались по наличию закрытия, а деньги-факт — по
статусу, и откаченная заявка давала в книге вывезенный объём при деньгах-оценке. Теперь на статус
переходят вместе `volumeM3`, `weightTons`, `removals`, подтверждённые талонами величины и
`volumeOrderedM3`: перевод одного поля без соседних положил бы объём в одну клетку и ноль вывозов
в соседнюю. День отнесения по-прежнему берётся у закрытия при любом статусе (З6): откаченная
заявка остаётся в своём месяце и лишь перестаёт быть вывозом.

### Р3. Прочерк — одно правило для трёх денег

Деньги каждой величины — `null` (прочерк), когда у всего её объёма нет цены; число, когда цена есть
хотя бы у части, и тогда портал подписывает «без цены … м³» (правило Р5 ADR 0193, теперь общее).
Ноль сам по себе этого не различает: после сложения атомов он значит и «цены не было», и «оценивать
было нечего».

### Р4. Две новые строки качества — безусловно

- «Заявок вывоза без заказанного объёма» — план этих заявок взят из закрытия (З3), знаменатель —
  заявки объёмных типов;
- «Выполненных заявок вывоза без закрытия» — по Р2 такая заявка даёт вывоз без объёма и денег.
  Сменой статуса её не создать («Выполнена» требует закрытия), но бывают старые данные и смена типа
  выполненной контейнерной операции на вывоз правкой (сверка единиц при правке типа срабатывает
  только при наличии закрытия).

Обе строки не зависят от данных прода (З11): ноль безвреден, а молчание — нет. Строка «Закрытий
вывоза без фактической даты» остаётся на закрытии; «Вывозов без принятого талона» — на статусе,
как сами вывозы.

### Р5. Ответ ручки только добавляет поля; старые снимаются по полу клиента

Портал ответ сервера схемой не проверяет, а вкладка со старой сборкой живёт сколько угодно и читает
`volumeM3`/`totalCost` без проверки; границы ошибок в портале нет, и снятие этих полей дало бы белый
экран всего портала. Поэтому выпуск только добавляет поля, а прежние (`volumeM3`, `volumeOrderedM3`,
`totalCost`, `costEstimated`) считаются прежней формулой с пометкой `@deprecated`. Снимаются они
отдельным выпуском, только когда пол клиента на проде станет **выше 6** — значения
`CLIENT_CONTRACT`, с которым раздаётся этот выпуск; тогда же поднимается `REQUIRED_CLIENT_FLOOR`.
Контракт клиента этим выпуском не поднимается.

Обратное направление — новая сборка против старого сервера (окно выката, вкладка после
`deploy-auto --previous`) — закрыто на портале: без новых полей вкладка показывает заглушку
«обновите страницу» вместо таблицы.

### Р6. Портал: четыре числовых столбца и «Итого» строкой таблицы

Столбцы и подписи — по З1, З2, З7, З8; окно площадки повторяет их по видам отходов. Общая
`DataTable` получила необязательную итоговую строку: страница передаёт готовую закреплённую
`Table.Summary` с итогом сервера (портал сумм не считает), а таблица вычитает её измеренную высоту
из высоты прокрутки. Полоса качества на десктопе стоит над таблицей: под таблицей высотой 100 % её
обрезал `overflow: hidden` вкладок.

### Р7. Книга меняется, лента об этом молчит

По Р2 книга Excel, выгруженная заново за прошлый месяц, может показать на один-два вывоза меньше
(возвраты бывают изредка, З11). Об этом говорят методика книги и оговорки формы выгрузки; лента
обновлений объявляет только новую статистику (З12).

## Следствия

- у атома вывоза четыре новых поля; загрузчики заказа ТС и механизации заполняют их нулями;
- сверка вкладки с книгой идёт по величинам, у которых в книге есть пара (вывезенное, вывозы,
  деньги-факт); «Заказано» и «По талонам» стерегут внутренние равенства и равенство плана оценке;
- список объёмных типов — одна константа загрузчика, вкладка её переиспользует;
- «По талонам» может быть больше «Вывезено» (З4) — расхождение видно в карточке заявки.

## Выкат

Выпуск 111 (`0.1.100.0209`), схема не меняется: миграция `0343` только пишет ленту. Окно выката
определяется в конце реализации (З13); вводные — на проде не выкачено окно 0327–0342, `deploy-auto`
выкатывает `main` целиком и запускается пользователем на VPS, push уносит неопубликованные коммиты
пользователя и делается только с его согласия. Пол клиента этим выпуском не трогается (Р5).
