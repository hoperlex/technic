# ADR 0006. Верификация адресов грузоперевозок через DaData (жёсткая модель)

- Статус: Принято
- Основано на: [ADR 0004](0004-vehicle-requests.md) (модуль «Заказ ТС»)
- Связано: `packages/contracts/src/vehicle-requests.ts` (`addressMetaSchema`,
  `verifiedAddressMetaSchema`, `isAddressVerified`), `apps/api/drizzle/0013_freight_address_meta.sql`,
  `apps/api/src/db/schema.ts`, `apps/api/src/routes/vehicle-requests.ts`, `apps/web/src/api/dadata.ts`,
  `apps/web/src/pages/vehicle/AddressAutoComplete.tsx`,
  `apps/web/src/pages/vehicle/FreightTransportRequestsTab.tsx`

> **Пересмотр решения.** Первая редакция ADR принимала «мягкую» модель (`manual` разрешён,
> помечается). По требованию бизнеса модель ужесточена: адрес погрузки/разгрузки **обязателен
> и должен быть верифицирован**; неверифицированный/`manual` ввод на запись не принимается.
> Эскейп для непочтовых точек через комментарий рассмотрен и **отклонён**.

## Контекст

Единственные свободно вводимые адреса в модуле — `loadingLocation` / `unloadingLocation`
(места погрузки/разгрузки грузоперевозки). До этого — `text` с ограничением `CHECK not-blank`;
пользователь мог записать произвольную неверифицированную строку. Адрес объекта заявки
(`object_id → construction_objects`) уже верифицирован выбором из справочника, спецтехника
адресных полей не имеет.

Задача — **исключить неверифицированные адреса в поле адреса**. Доменная оговорка про непочтовые
точки (стройплощадка, карьер, «трасса М-4, 850 км») в первой редакции вела к мягкой модели; она
пересмотрена: такие точки через поле адреса не оформляются.

## Решения

1. **Жёсткая модель (блокирующая).** Адрес погрузки/разгрузки **обязателен** и должен быть
   **верифицирован**: принимается только выбор из подсказки DaData (`resolved`+ФИАС) либо из
   справочника объектов (`object`). Свободный/`manual` ввод на запись **отклоняется** — на
   фронте (форму нельзя отправить) и в контрактах (`verifiedAddressMetaSchema`). Серверной
   пере-проверки через «Стандартизацию» (Cleaner API) по-прежнему нет: backend доверяет
   `fiasId` из подсказки, внешних вызовов в write-path нет.
2. **Строка + метаданные.** Каноническая строка — в `loading_location` / `unloading_location`
   (`text NOT NULL`, прежние CHECK). Рядом — `loading_address` / `unloading_address` (`jsonb`)
   с происхождением и ФИАС/гео. Для новых заявок метаданные всегда заданы и верифицированы
   (гарантия — контракты). `jsonb NULL` на уровне БД остаётся только ради легаси-строк,
   созданных до ужесточения; при следующем редактировании такие строки требуют выбора адреса.
3. **Схема метаданных** (`addressMetaSchema`, `.strict()`): `source` (`resolved|manual|object`),
   `fiasId?`, `fiasLevel?`, `geoLat?`, `geoLon?`. `fiasId` — не строгий UUID (DaData отдаёт разные
   GUID), а строка ≤64. CHECK в БД проверяет только форму (`jsonb object` + ключ `source`);
   содержимое валидирует Zod. На запись поверх надет `verifiedAddressMetaSchema` (refine по
   `isAddressVerified`).
4. **Критерий верификации** (`isAddressVerified`): `source==='object'` **или** (`source==='resolved'`
   и есть `fiasId`). `manual` и `null` — не верифицированы.
5. **`source: 'object'`** заложен в enum как forward-compat (выбор точки из справочника объектов),
   UI-пикер — следующий инкремент; сейчас на запись формируется только `resolved`. `manual`
   остаётся в enum лишь для чтения легаси-строк.
6. **Frontend.** Тонкий `AddressAutoComplete` поверх AntD `AutoComplete` (debounce 250мс,
   AbortController, порог 3 символа). Meta ставится, только если строка точно совпала с подсказкой;
   свободный ввод → `null`. Отправка формы **блокируется**, пока адрес погрузки и разгрузки не
   выбраны из подсказок (инлайн-ошибка на поле). В таблице — значок статуса (✓ верифицирован /
   ⚠ легаси-вручную).
7. **Секреты/ops.** Токен «Подсказок» уходит в браузер (build-time `VITE_DADATA_SUGGEST_TOKEN`) —
   **обязательно** ограничить его по домену в кабинете DaData. В деплое разрешить
   `suggestions.dadata.ru` в CSP `connect-src`. Секретный ключ «Стандартизации» не заводится
   (жёсткой модели «Подсказок» достаточно).

## Последствия

- (+) Все новые адреса — verified (ФИАС/гео); неверифицированных в поле адреса не появляется.
- (+) Нет платных вызовов и серверной зависимости в пути записи (доверие `fiasId` подсказки).
- (−) **Токен «Подсказок» — жёсткая зависимость для грузоперевозок.** Без него (не задан при
  сборке веба) подсказки недоступны → адрес не верифицировать → заявку на грузоперевозку создать
  нельзя. `VITE_DADATA_SUGGEST_TOKEN` обязателен на build веба (dev и прод).
- (−) Не строгая гарантия подлинности: клиент теоретически подделает `fiasId` (для внутреннего
  портала приемлемо). Серверная пере-проверка через Cleaner API — в бэклоге.
- (−) Непочтовые точки (карьер, «трасса, км») через поле адреса не оформляются — компромисс
  жёсткой модели (эскейп в комментарий отклонён бизнесом).
- (−) Легаси-строки (до ужесточения) могут иметь `NULL`/`manual`-адрес; помечаются ⚠ и требуют
  выбора адреса при следующем редактировании.

## Отложено (backlog)

- **Жёсткая серверная верификация** через Cleaner API (`token` + `secret`): порог `qc`/`fias_level`,
  канонизация, политика на 5xx/таймаут DaData, 422 при непрохождении.
- **Выбор точки из справочника объектов** (`source: 'object'`) как альтернатива внешнему адресу.
- Те же подсказки в форме справочника объектов (`ObjectsTab`) и, при желании, гео-точка на карте.
