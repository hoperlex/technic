# ADR 0005. Верификация адресов грузоперевозок через DaData (мягкая модель)

- Статус: Принято
- Основано на: [ADR 0004](0004-vehicle-requests.md) (модуль «Заказ ТС»)
- Связано: `packages/contracts/src/vehicle-requests.ts` (`addressMetaSchema`, `isAddressVerified`),
  `apps/api/drizzle/0013_freight_address_meta.sql`, `apps/api/src/db/schema.ts`,
  `apps/api/src/routes/vehicle-requests.ts`, `apps/web/src/api/dadata.ts`,
  `apps/web/src/pages/vehicle/AddressAutoComplete.tsx`,
  `apps/web/src/pages/vehicle/FreightTransportRequestsTab.tsx`

## Контекст

Единственные свободно вводимые адреса в модуле — `loadingLocation` / `unloadingLocation`
(места погрузки/разгрузки грузоперевозки). До этого — `text` с единственным ограничением
`CHECK not-blank`; пользователь мог записать произвольную неверифицированную строку. Адрес
объекта заявки (`object_id → construction_objects`) уже верифицирован выбором из справочника,
спецтехника адресных полей не имеет.

Задача — снизить долю неверифицированных адресов, не ломая легитимные сценарии. Важная
доменная оговорка: точки погрузки/разгрузки **часто не почтовые адреса** (стройплощадка,
карьер, «трасса М-4, 850 км»), поэтому жёсткий reject по качеству адреса недопустим.

## Решения

1. **Мягкая модель, а не блокирующая.** Подсказки DaData (сервис «Подсказки») дают UX и
   структуру; серверная пере-проверка через «Стандартизацию» (Cleaner API) на этапе каркаса
   **не делается**. Backend доверяет данным выбранной подсказки. `manual` (свободный ввод)
   разрешён, но помечается. Внешних вызовов в write-path нет — доступность/латентность/цена
   DaData не влияют на создание заявки.
2. **Строка + метаданные, аддитивно.** Каноническая строка остаётся в `loading_location` /
   `unloading_location` (`text`, все прежние CHECK сохранены). Рядом — `loading_address` /
   `unloading_address` (`jsonb NULL`) с происхождением и ФИАС/гео. `NULL` = введён вручную.
   Обратная совместимость: старые строки = `NULL` = не верифицированы.
3. **Схема метаданных** (`addressMetaSchema`, `.strict()`): `source` (`resolved|manual|object`),
   `fiasId?`, `fiasLevel?`, `geoLat?`, `geoLon?`. `fiasId` — не строгий UUID (DaData отдаёт
   разные GUID), а строка ≤64. CHECK в БД проверяет только форму (`jsonb object` + ключ `source`);
   содержимое валидирует Zod.
4. **Критерий верификации** (`isAddressVerified`): `source==='object'` **или**
   (`source==='resolved'` и есть `fiasId`). `manual` и `null` — не верифицированы.
5. **`source: 'object'`** заложен в enum как forward-compat (выбор точки из справочника
   объектов), но UI-пикер — следующий инкремент; сейчас формируются только `resolved`/`manual`.
6. **Frontend.** Тонкий `AddressAutoComplete` поверх AntD `AutoComplete` (debounce 250мс,
   AbortController, порог 3 символа). Meta ставится, только если строка точно совпала с
   подсказкой; свободный ввод → `null`. Без токена (`VITE_DADATA_SUGGEST_TOKEN`) — деградирует
   в обычный `Input`. В таблице — значок статуса (✓ верифицирован / ⚠ вручную).
7. **Секреты/ops.** Токен «Подсказок» уходит в браузер — **обязательно** ограничить его по
   домену в кабинете DaData. В деплое разрешить `suggestions.dadata.ru` в CSP `connect-src`.
   Секретный ключ «Стандартизации» не заводится (не нужен мягкой модели).

## Последствия

- (+) Дефолтный путь ведёт к verified-адресу с ФИАС/гео; `manual` — меньшинство, видимо помечен.
- (+) Нет внешней зависимости и платных вызовов в пути записи; сборка/дев работают без токена.
- (+) Аддитивная миграция, обратимо; контракт-тесты «Заказ ТС» и «Мусора» не затронуты.
- (−) Не строгая гарантия: клиент теоретически подделает `fiasId` (для внутреннего портала
  приемлемо). Жёсткая серверная пере-проверка — в бэклоге.
- (−) Строка и метаданные могут рассинхронизироваться при обходе UI (frontend всегда шлёт их
  вместе; сервер не сверяет соответствие).

## Отложено (backlog)

- **Жёсткая серверная верификация** через Cleaner API (`token` + `secret`): порог `qc`/`fias_level`,
  канонизация, политика на 5xx/таймаут DaData, 422 при непрохождении. Ручка «запрещать `manual`».
- **Выбор точки из справочника объектов** (`source: 'object'`) как альтернатива внешнему адресу.
- Те же подсказки в форме справочника объектов (`ObjectsTab`) и, при желании, гео-точка на карте.
