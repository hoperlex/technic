# План: правки бланков путевых листов — 4-П, ЭСМ-2, форма № 3

- Статус: редакция 3 от 20.08.2026 — **реализовано**, не закоммичено. Этапы 1–8 закрыты; сверх
  плана: расшифровка подписи печатается видом «Фамилия И.О.» (ключ `driver_short_name`), а
  объединение даты ЭСМ-2 сужено до `BH2:BO3` — `BH2:BT3` обрезал подпись «Форма по ОКУД», которая
  печатается переполнением влево (поймано визуальной сверкой, закрыто тестом)
- Свободные номера на момент составления: миграция `0164`, ADR `0127` (`0126` зарезервирован
  `assignment-periods-plan.md`); номера берутся заново перед выкатом
- Затрагивает: [ADR 0037](adr/0037-freight-transport-waybill.md) п. 10 (снимок и печать),
  [ADR 0041](adr/0041-waybill-freight-only-and-printing.md) (печать, ориентация),
  [ADR 0060](adr/0060-esm2-weekly-waybill.md) (недельный лист),
  [ADR 0071](adr/0071-blank-waybill-and-form3-task.md) (что портал в бланк не печатает),
  [ADR 0066](adr/0066-phone-single-format.md) (вид телефона)

## 1. Что просят

Три бланка выходят из принтера с погрешностями — часть графы заполнена не тем, часть блоков
бланка портал заполнять не будет никогда и на бумаге читается приглашением вписать от руки.

### Форма 4-П

1. Дата в формате `дд.мм.гггг` (сейчас `2026-08-23`).
2. «Вид сообщения» — обязательное поле на уровне UI, выпадающим списком: городское, пригородное,
   междугороднее; по умолчанию «пригородное».
3. Блок «Количество отработанных часов» убрать целиком — вместе с рамкой поля и линиями подписи.
4. Графа «В чьё распоряжение (наименование и адрес заказчика)» заполняется не тем: должен
   печататься заказчик — «Генеральный подрядчик ООО «СУ-10»» и адрес его офиса.
5. В графах «(расшифровка подписи)» водителя печатать имя водителя видом «Фамилия И.О.».

### Форма ЭСМ-2

1. Номер и дата листа — единым видом с заголовком бланка и на одной с ним линии.
2. Графа «Заказчик» — та же ошибка, что в п. 4 у 4-П.
3. Наименование и адрес объекта печатать один раз — в шапке графы, а не повторять в каждом
   из семи дней недели.
4. То же наименование и адрес — в шапку графы «Объект» на обороте.
5. Блок «коды объектов» убрать целиком.

### Форма № 3

1. Дата в формате `дд.мм.гггг`.
2. В графах «(расшифровка подписи)» водителя печатать имя водителя видом «Фамилия И.О.».
3. «Вид сообщения» — тот же обязательный список, что и в 4-П.
4. Блок «Водительское удостоверение проверил» убрать, а блок «Водитель по состоянию здоровья к
   управлению допущен, алкотест пройден» поднять на освободившееся место.

Существенное для этих правок:

- **Лист печатается из снимка**, а не из справочников (ADR 0037 п. 10): правка сборщика меняет
  только листы, выписанные после неё. Совместимость со старыми снимками живёт в
  [`snapshotForPrint`](../packages/contracts/src/waybills.ts#L570).
- **Скрипт разметки умеет** вписывать значения, стирать содержимое (`clear`), снимать нижнюю
  границу (`unline`), снимать объединение (`unmerge`), переносить содержимое (`move`), ставить
  `shrinkToFit`/`wrapText`, брать шрифт графы-эталона (`font`), поднимать высоту строки (`height`).
  **Не умеет**: снимать рамку целиком (нужна для 4-П п. 3) и создавать объединение (нужно для
  ЭСМ-2 п. 1).
- **Заказчика в портале нет как реквизита**: у объекта строительства ([schema.ts:183](../apps/api/src/db/schema.ts#L183))
  только код, наименование и адрес; у контрагента ([`counterparties`](../apps/api/src/db/schema.ts))
  нет ни адреса, ни телефона, а ООО «СУ-10» заведено там сидом
  [0025](../apps/api/drizzle/0025_counterparties_seed.sql) без реквизитов.
- **Вид сообщения** — свободная строка (`z.string().max(50)`,
  [vehicle-routes.ts:138](../packages/contracts/src/vehicle-routes.ts#L138)), в UI обычный `Input`
  в трёх окнах: [VehicleAssignModal.tsx:1772](../apps/web/src/pages/vehicle/VehicleAssignModal.tsx#L1772),
  [VehicleRouteEditModal.tsx:353](../apps/web/src/pages/vehicle/VehicleRouteEditModal.tsx#L353),
  [VehicleRouteCorrectionModal.tsx:327](../apps/web/src/pages/vehicle/VehicleRouteCorrectionModal.tsx#L327).
  Перегон подставляет «городское» кодом ([VehicleRelocationModal.tsx:122](../apps/web/src/pages/vehicle/VehicleRelocationModal.tsx#L122)).

## 4. Развилки и решения заказчика

| Развилка | Решение |
| --- | --- |
| Откуда реквизиты заказчика | **Настройка портала, одна на все листы**: наименование, адрес, телефон правятся SQL по runbook'у, как реквизиты организации |
| Телефон в графе «Заказчик» ЭСМ-2 | Телефон **заказчика** (из той же настройки), а не ответственного за объект |
| Объект в 4-П | Только в задании водителю (`task_from`/`task_to`), как сегодня |
| Формат даты у выданных листов | **Только новые листы**: снимок печатается как выдан, ISO-дата старого листа остаётся ISO |

Следствия, которые эти решения тянут за собой:

- Графа ЭСМ-2 «Заказчик» перестаёт нести телефон ответственного за встречу машины. Контакт
  ответственного остаётся в заявке и в кабинете водителя (ADR 0122) — на бумаге его больше нет.
- Ключи `customer_name`/`customer_address`/`customer_phone` меняют смысл: до правки это объект
  заявки, после — заказчик портала. Старые снимки остаются с прежним содержимым, и повторная
  печать выданного листа даёт ровно то, что было выдано.
- Настройка «одна на все листы» верна, пока генподрядчик один. Появится второй — реквизит
  переезжает к объекту строительства; это отдельная работа, и в ADR она названа прямо.

## 5. Данные

### 5.1 Реквизиты заказчика (миграция `0164`)

Таблица-одиночка: одна строка на портал, как `organizations.is_primary` отвечает «чей это лист»,
так эта — «в чьё распоряжение он выписан».

```sql
CREATE TABLE waybill_customer (
  -- Одиночка: строка ровно одна, вторую запрещает первичный ключ с CHECK.
  id            boolean PRIMARY KEY DEFAULT true CHECK (id),
  name          text NOT NULL DEFAULT '',
  address       text NOT NULL DEFAULT '',
  phone         text NOT NULL DEFAULT '',
  updated_by    uuid REFERENCES users(id) ON DELETE SET NULL,
  updated_at    timestamptz NOT NULL DEFAULT now()
);

INSERT INTO waybill_customer (name, address, phone)
VALUES (
  'Генеральный подрядчик ООО «СУ-10»',
  'г. Москва, ул. Полковая, д. 3, стр. 5',
  '+7 (495) 616-23-22'
)
ON CONFLICT (id) DO NOTHING;
```

Экрана у настройки нет — как и у справочника юрлиц (бэклог ADR 0037); правка через SQL описывается
в runbook'е. Телефон печатается через `formatPhone` (ADR 0066) — тем же ходом, что телефон
организации в шапке: единый вид у обеих граф бланка.

Чтение — в обоих сборщиках снимка, одной функцией `loadWaybillCustomer(tx)` в
[`waybill-issue.ts`](../apps/api/src/services/waybill-issue.ts): второе её написание в ЭСМ-2
разошлось бы с первым при первой же правке.

### 5.2 Ключи снимка

[`WAYBILL_SNAPSHOT_KEYS`](../packages/contracts/src/waybills.ts#L452):

- **добавляется** `driver_short_name` — «Дегтярь И.В.»: расшифровка подписи узкая, и полное ФИО
  в неё не встаёт. Отдельным ключом, а не сокращением при печати: снимок обязан помнить и то, как
  имя напечатано на выданной бумаге. Сокращает `formatNameWithInitials`
  ([person-name.ts](../packages/contracts/src/person-name.ts)) — то же правило, каким бланк 4-П уже
  печатает контакты задания (запись ровно из трёх слов, иначе как есть); приватная
  `contactNameLabel` в `vehicle-routes.ts` теперь ссылается на неё же.
- **добавляется** `object_line` — «наименование и адрес объекта» одной строкой. Один ключ, а не
  пара: пустой адрес в паре давал бы осиротевшую запятую, а склейку в бланке не поправить.
  Заполняется обоими сборщиками (у 4-П — объект заявки шапки; печатается только в ЭСМ-2).
- **удаляются** `day1_object`…`day7_object` — графа дней больше не печатается (ЭСМ-2 п. 3).
- **смысл меняют** `customer_name`, `customer_address`, `customer_phone` — теперь реквизиты
  заказчика из `waybill_customer`, а не объект заявки. Комментарии в списке ключей переписываются.

### 5.3 Формат дат

Формат `дд.мм.гггг` в контрактах, рядом с `formatWaybillNumber`: `formatWaybillDate(iso)`.
Применяется к `waybill_date` и `driver_license_issued_on` в обоих сборщиках (в ЭСМ-2 дата листа уже
разложена по клеткам `dd`/`mm`/`yyyy` и собирается тем же способом — склейка заменяется вызовом).

Выданных листов формат не касается (решение §4): их снимок печатается как выдан, и старый лист
выходит из принтера с датой `2026-08-23`. Перекладывать её при печати портал не берётся — правило
«повторная печать даёт тот же документ» (ADR 0037 п. 10) сильнее единообразия бумаг разных лет.

Ходов совместимости в [`snapshotForPrint`](../packages/contracts/src/waybills.ts#L570) три (третий
— `task_contacts`, он был там до этой работы). Первый — `object_line`: нет ключа, значит он собирается из `customer_name` + `customer_address` старого
снимка. Это ровно то, что в старых листах ЭСМ-2 лежало в графе «Заказчик» (объект), и без этого
хода повторная печать старого недельного листа вышла бы из принтера **без объекта вовсе**: дневные
графы в новом бланке не размечены, а шапка ждёт ключа, которого в снимке нет. Признаком служит
отсутствие ключа, а не пустое значение: у нового листа пустой объект значит «объекта в заявке не
было».

Второй — `driver_short_name`: нет ключа, значит он собирается сокращением `driver_fio` того же
снимка. Полное ФИО в снимке есть всегда, и без этого хода повторная печать оставила бы расшифровки
пустыми — напечатала бы меньше, чем печатает та же кнопка на соседнем листе.

### 5.4 Что станет с уже выданными листами

Правило перевыпуска отвечает на это твёрдо, и оно не про бланк, а про заявку.
[`esm2SyncPlan`](../packages/contracts/src/waybills.ts#L305) сверяет три вещи: **набор недель**
(срок заявки), **машину** и **машиниста**. Разошлось — номер аннулируется и выписывается новый;
сошлось — не трогается ничего, ни один номер не сгорает. Ни реквизиты заказчика, ни формат даты,
ни разметка бланка в эту сверку не входят вовсе: **ни один лист от этой работы не перевыпустится**.
У 4-П и формы № 3 перевыпуска нет и подавно — их выписывает человек на рейс.

Но печать выданного листа идёт **новым шаблоном со старым снимком**: файл бланка читается с диска
на каждый запрос ([waybills.ts:116](../apps/api/src/routes/waybills.ts#L116)), а снимок берётся из
`waybills.data`. Значит правки вёрстки достаются и старым листам, а правки данных — нет:

| Правка | Новый лист | Повторная печать выданного |
| --- | --- | --- |
| Блок отработанных часов 4-П, коды объектов ЭСМ-2, блок удостоверения № 3 | нет | **тоже нет** — блока нет в бланке |
| Имя водителя в расшифровках | «Дегтярь И.В.» | **печатается** — сокращается из `driver_fio` старого снимка |
| Шапка ЭСМ-2: номер и дата единым видом | да | **да** — ключи те же, изменилась вёрстка |
| Объект в шапке графы ЭСМ-2 | из `object_line` | из `customer_name` + `customer_address` (§5.3) |
| Объект в строках дней ЭСМ-2 | не печатается | **не печатается** — графа не размечена |
| Заказчик в графе «В чьё распоряжение» / «Заказчик» | реквизиты портала | старое содержимое снимка — объект заявки |
| Формат даты | `дд.мм.гггг` | `ГГГГ-ММ-ДД`, как выдан |

Отсюда две вещи, которые надо принять сознательно:

1. У старого листа ЭСМ-2 объект напечатается дважды — в графе «Заказчик» (там он лежит в снимке)
   и в шапке графы объекта (туда его положит запасной ход). Повтор лучше потери: без запасного
   хода объект исчезает с бумаги совсем.
2. Бумаги, выданные до и после выката, различаются видом даты и содержанием графы заказчика. Это
   цена правила «повторная печать даёт тот же документ» — иначе портал переписывал бы выданное.

## 6. Разметка бланков

Адреса выверены по распакованным шаблонам (`xl/worksheets/sheet1.xml`); в скобках — объединение,
если графа им задана.

### 6.1 Скрипт: две новые операции

| Операция | Зачем | Как устроена |
| --- | --- | --- |
| `unbox: string[]` | 4-П п. 3: у поля «Количество отработанных часов» рамка со всех сторон (`borderId=3`), а `unline` снимает только низ | по образцу `unlineCells`: копия рамки без всех четырёх сторон, копия записи стиля, кэш по исходному стилю |
| `merge: string[]` | ЭСМ-2 п. 1: номер и дата обязаны занять ту же высоту, что заголовок (`T2:AL3`), иначе на одну линию с ним они не встают | дописывает `<mergeCell>` и увеличивает `count`; накрытые ячейки чистятся, чтобы книга не считалась повреждённой |

Порядок в `mark()` — `unmerge → merge → move → cells → clear → unbox/unline → shrink/wrap → font → height → pageSetup`: адреса `cells` описывают бланк, каким он уходит на печать.

### 6.2 Форма 4-П (`FORM_4P`, [строка 90](../apps/api/scripts/mark-waybill-templates.ts#L90))

**Убрать блок «Количество отработанных часов»** — он весь в строках 16–17, правее движения горючего:

- `clear`: `CR16` («Количество отработанных часов»), `EM17` («(подпись)»), `EW17` («(расшифровка подписи)»);
- `unbox`: `DX16:EJ16` — поле в рамке;
- `unline`: `EM16:ET16`, `EW16:FJ16` — линии подписи и расшифровки.

**Имя водителя в расшифровки** (`cells`, `{{driver_short_name}}`):

- `DY32` (`DY32:FJ32`) — над «(расшифровка)» блока «Автомобиль принял. Водитель»;
- `DN37` (`DN37:EA37`) — над «(расшифровка подписи)» блока «Сдал водитель».

Обе ячейки в бланке есть, набраны Arial 8 по центру — тем же, чем `{{driver_fio}}` в шапке;
`font` не нужен. Соседние графы механика (`EK37`, `ET37`) не трогаем: их подписывает человек.

Графа «В чьё распоряжение» адресами не меняется (`A30`, `A31`) — меняется только то, что в
`customer_name`/`customer_address` кладёт сервер.

### 6.3 Форма ЭСМ-2 (`FORM_ESM2`, [строка 257](../apps/api/scripts/mark-waybill-templates.ts#L257))

**Шапка: номер и дата.** Заголовок «ПУТЕВОЙ ЛИСТ» — `T2:AL3`, Tahoma 18 pt, прижат к низу;
номер (`AM3`) и дата (`BH2`) — Times 11 pt bold и на разных строках, отчего и «пляшут».

- `merge`: `AM2:BE3` (номер) и `BH2:BT3` (дата) — обе величины занимают ту же пару строк, что
  заголовок, и садятся с ним на одну линию;
- `cells`: `AM2` ← `№ {{waybill_series}}{{waybill_number}}`, `BH2` ← `{{waybill_date}}`
  (прежние `AM3`/`BH2` из списка уходят);
- `font`: обе — эталоном `T2` вместо `AO9`; `shrink`: обе — длину номера серии бланк не выбирает,
  а 18 pt в 19 колонок влезает впритык;
- `height`: строки 2 и 3 остаются 14 pt — объединение уже даёт 28 pt под кегль 18.

Подпись «от» (`BF2:BG3`) стоит между ними и не пересекается ни с одним новым объединением.

**Объект в шапке графы вместо дней.**

- `cells`: `D13` (`D13:AH17`, лицевая) ← `Наименование и адрес объекта⏎{{object_line}}⏎⏎Выполняемая работа`;
- `cells`: `I102` (`I102:AO104`, оборот) ← та же вставка в подпись графы «Объект»;
- из `cells` уходят `D19`, `D23`, `D27`, `D31`, `D35`, `D39`, `D43` — дневные графы больше не
  печатаются. Числа месяца (`C19`…`C43`, `B106`…`B130`) остаются: ими лист и ведут.

Следствие, которое надо назвать вслух: пустая графа дня перестаёт означать «портал не знает,
работала ли машина в этот день». Признак срока заявки уходит с бумаги — за него теперь отвечает
только период в шапке («Период работы: с `__` по `__`»).

**Коды объектов** (`clear`): `AL143` («коды объектов») и три строки списка —
`AP144`, `AT144`, `AW144`, `AZ144`, `BD144`, `BG144`, `BJ144`, `AP145`, `AT145`, `AW145`, `AZ145`,
`BD145`, `BG145`, `BJ145`, `AP146`, `AT146`, `AW146`, `AZ146`, `BD146`, `BG146`. Рамки у блока нет
(`borderId=0` у всех), фигур рисунка в этих строках нет — стирания текста достаточно.

### 6.4 Форма № 3 (`FORM_LEG3`, [строка 212](../apps/api/scripts/mark-waybill-templates.ts#L212))

**Блок «Водительское удостоверение проверил»** — это графа диспетчера бланка: подпись `A37`
(`A37:AU37`), линии `Q39:Y39` и `AA39:AR39`, их подписи `Q40`/`AA40` (уже стёрты нынешней
разметкой вместе с `A39`/`AA39`).

- `unmerge`: `A37:AU37` — иначе поднятый текст обрежется по границе объединения (он набран в
  более широком `A42:AX42`);
- `move`: `A42` → `A37`, `A43` → `A38` — блок «Водитель по состоянию здоровья…» встаёт на
  освободившееся место; `moveCell` заменяет ячейку целиком, поэтому отдельный `clear` для `A37`
  не нужен, а строки 42–43 остаются пустыми;
- `unline`: `Q39:Y39`, `AA39:AR39` — линии удалённой графы; из `clear` уходят `A39`, `AA39`
  (их стирает перенос), `Q40`/`AA40` остаются.

**Имя водителя в расшифровки** (`cells`, `{{driver_short_name}}`): `AA48` (`AA48:AR48`, над «(расшифровка подписи)» блока
«Автомобиль принял / водитель») и `AA55` (`AA55:AR55`, блок «Автомобиль сдал / водитель»). Обе —
Arial 8 по центру, тем же, чем `{{driver_fio}}` в шапке (`M18`).

Графы механика (`BK56`, `BU56`) не трогаем.

## 7. UI: вид сообщения

- В контрактах — `COMMUNICATION_KINDS = ['городское', 'пригородное', 'междугороднее']` и
  `DEFAULT_COMMUNICATION_KIND = 'пригородное'` рядом со схемой рейса
  ([vehicle-routes.ts](../packages/contracts/src/vehicle-routes.ts)).
- Схема запроса **не ужесточается**: `z.string().max(50)` остаётся. Ужесточение отбило бы правку
  рейсов, у которых графа пуста (все, выписанные до этой работы), а обязательность просили
  «на уровне UI».
- В трёх окнах `Input` заменяется на `Select` из этого списка — с `rules: [{ required: true }]`,
  **без** `allowClear` и без пункта «не выбрано»: очистить графу в окне нельзя, значение выбирается
  только из трёх:
  [VehicleAssignModal.tsx:1772](../apps/web/src/pages/vehicle/VehicleAssignModal.tsx#L1772),
  [VehicleRouteEditModal.tsx:353](../apps/web/src/pages/vehicle/VehicleRouteEditModal.tsx#L353),
  [VehicleRouteCorrectionModal.tsx:327](../apps/web/src/pages/vehicle/VehicleRouteCorrectionModal.tsx#L327).
- «Пригородное» стоит выбранным при открытии окна — и при заведении рейса, и при наследовании
  реквизитов от прошлого рейса машины, если у того графа пуста
  ([resources.ts:240](../apps/web/src/api/resources.ts#L240) описывает наследование). Пустым в
  портал через окно значение уже не уйдёт.
- Перегон продолжает подставлять «городское» — значение из списка, менять нечего.
- Значение вне списка (пришло от старого рейса) показывается как выбранное, а не стирается молча:
  иначе правка чужой графы уносила бы то, что напечатано на выданном листе.

## 10. Открытые вопросы и риски

- **О1. Кегль шапки ЭСМ-2.** 18 pt заголовка в объединение под номер влезает впритык; если на
  бумаге номер серии с префиксом ужимается до нечитаемого, кегль эталона снижается до Tahoma 14 —
  решение принимается по первому PDF, а не заранее.
- **Р1. Уход дневного объекта** (§6.3) снимает с бумаги единственный признак «в этот день машина
  на объекте числилась». Если бухгалтерия ведёт по нему сверку, правку придётся откатить или
  заменить признак иным (например, прочерком в днях вне срока).
- **Р2. Смена смысла `customer_*`** делает несравнимыми снимки до и после выката: одинаковый ключ
  в двух листах значит разное. Ловится это только чтением ADR, поэтому в нём — отдельный абзац,
  а в `database-schema.md` — дата разреза.
- **Р3. Две записи даты в обороте.** Листы, выданные до выката, печатаются с `2026-08-23`, после —
  с `23.08.2026` (решение §4). В подшивке за август это соседние страницы с разной записью одного
  дня; бухгалтерию об этом предупреждают строкой в runbook'е, а не оставляют находить самой.
- **Р4. Замена бланка бухгалтерией** обнулит все адреса §6: они выверены по нынешним файлам
  `templates/source/`. Это обычная цена разметки (ADR 0037), но правок стало больше, и в ADR
  фиксируется, что вместе с бланком переписывается и список операций, а не только `cells`.
