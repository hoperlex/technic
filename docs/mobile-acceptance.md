# Приёмка мобильной версии

Чек-лист ручной проверки адаптивной вёрстки ([ADR 0030](adr/0030-responsive-layout.md),
[ADR 0042](adr/0042-directories-on-phone.md) — справочники и администрирование карточками).
Автотесты (`pnpm --filter @technic/web test`) закрывают режим устройства, оболочку формы,
карточные списки, шиты фильтров и сортировки. Здесь — то, что проверяется только руками и
только на реальных устройствах.

## Как включить мобильный режим

```
(hover: none) and (pointer: coarse) and (max-width: 1024px)
```

**Изменением ширины окна браузера мобильный вид не проверяется** — режим включает не размер, а
устройство: у мыши он не включается никогда. Варианты проверки:

- реальный телефон или планшет — единственный способ проверить safe-area, камеру и клавиатуру;
- DevTools → device toolbar (эмулирует `pointer: coarse`) — годится для раскладки, но не для
  выреза экрана, камеры и поведения адресной строки.

Признак включённого режима: класс `is-mobile` на `<html>` и нижняя навигация вместо боковой.

## Устройства

| Устройство                                         | Что проверяется в первую очередь                                                        |
| -------------------------------------------------- | --------------------------------------------------------------------------------------- |
| iPhone (Safari), портрет и ландшафт                | вырез и «домашняя полоска», автозум полей, `100dvh` при скрытии адресной строки, камера |
| Android (Chrome), портрет                          | камера, экранная клавиатура поверх кнопок формы                                         |
| Планшет (тач), портрет и ландшафт 1024             | граница режима: при 1024 портал мобильный, при 1025 — десктопный                        |
| Десктоп с мышью, 1440×900 / 1280×800 / окно 600 px | регресс: вид не изменился ни на одной ширине                                            |

Базовый экран для раскладки — 360×640: если что-то не помещается, это видно там.

## Сквозные сценарии по ролям

### Штаб (свой объект, заявки до «В работе»)

- [ ] Вход с телефона: карточка формы по ширине экрана, поля не зумят страницу при фокусе
- [ ] В нижней навигации ровно два раздела: «Вывоз» и «Заказ ТС»
- [ ] Создание заявки на вывоз кнопкой в правом нижнем углу; форма открывается снизу во весь экран
- [ ] Объект подставлен и не меняется; тип заявки, тип мусора, объём — в одну колонку
- [ ] Дата: календарь открывается без клавиатуры; время набирается цифрами
- [ ] Файл прикрепляется; имя длинного файла не растягивает окно
- [ ] Сохранение; заявка появилась в списке карточкой с номером, статусом и объектом
- [ ] Правка своей «Новой» заявки из меню «⋯»; у заявки в работе пункт недоступен
- [ ] Тап по карточке открывает карточку заявки во весь экран, история читается

### Оператор вывоза (свои заявки, закрытие)

- [ ] В навигации один раздел — «Вывоз»
- [ ] В списке только свои заявки; колонки «Оператор» нет
- [ ] Тап по тегу статуса открывает список переходов снизу
- [ ] Перевод в «Выполнена» открывает окно закрытия
- [ ] Строка машины: тип во всю ширину, количество кнопками ±, объём и сумма под ними
- [ ] Кнопка «Снять камерой» открывает камеру; снимок прикрепляется талоном
- [ ] «Прикрепить талон» рядом принимает файл из галереи или из файлов
- [ ] Без талона закрытие не проходит — предупреждение видно
- [ ] Сверка «заявлено ↔ вывезено» и стоимость по прайсу видны до нажатия «Выполнена»

### Оператор оргтехники (заявки на обслуживание)

Столбец состояния, заморозка и планка приёмки —
[ADR 0125](adr/0125-service-request-cycle-changes.md).

- [ ] В карточке заявки состояние читается двумя местами: тег статуса в заголовке и **одна**
      подпись строкой — «Вам: согласовать смету», «Ждёт сервис», «Отложена: ждём запчасть».
      Прежних строк «Ждёт» и «От вас требуется» на карточке нет
- [ ] Подпись состояния — **текст, а не ссылка**: тап по ней открывает карточку заявки, как и тап
      по любому другому месту; действия остаются в шите «⋯»
- [ ] «Отложить» из шита «⋯»: без причины окно не сохраняется, сообщение видно над клавиатурой
- [ ] После заморозки: тег «Отложена», подпись с причиной, «В статусе: сегодня» — возраст обнулился
- [ ] У отложенной в шите остаются «Возобновить», «Отменить» и «Обсуждение»; правки, смены
      срочности, «Записать перемещение техники» и «Удалить» там нет
- [ ] Перемещение записывают из карточки заявки: ссылка «Записать перемещение» стоит у поля «Какой
      аппарат» — у кого есть право справочника. В шите списка этого пункта нет ни в одном статусе
- [ ] «Возобновить» называет статус, в который заявка вернётся, и возвращает именно в него;
      возраст снова «сегодня», подпись состояния стала обычной («Ждёт сервис», «Вам: …»)
- [ ] Приёмка без закрывающего документа не проходит: кнопка неактивна, окно объясняет — нужен
      акт, счёт **или** гарантийный талон (комплект не требуется)
- [ ] Документ прикладывается прямо в окне приёмки (камерой или файлом из галереи), после чего
      кнопка становится активной **не закрывая окна**, и приёмка проходит
- [ ] У заявки, предъявленной без бумаг, подпись состояния читается как «Вам: нужен закрывающий
      документ» и ведёт в то же окно приёмки
- [ ] Поля «Желаемый срок» в форме заявки нет, фильтра «Просроченные» в шите фильтров нет

### Диспетчер / менеджер

- [ ] Фильтры списка: кнопка «Фильтры» со счётчиком, значения во всю ширину
- [ ] Выбор значения не перезагружает список; «Применить» — один запрос; «Отмена» ничего не меняет
- [ ] Фильтр «Тип ТС» — набор: несколько позиций тегами, лишние свёрнуты в «+N», счётчик
      кнопки «Фильтры» считает набор одним фильтром; «Сбросить» чистит его целиком (ADR 0124)
- [ ] «Сортировка»: поле и направление; список пересобрался, страница вернулась на первую
- [ ] Листание: «Всего: N» и стрелки; фильтры и сортировка сохранились
- [ ] Назначение оператора при переводе в работу — шит с выбором
- [ ] Заказ ТС: назначение техники (принадлежность → арендодатель → машина), ставки в столбец
- [ ] Закрытие заказа ТС: отработанное и стоимость друг под другом, сумма пересчитывается
- [ ] Справочники: записи карточками, поиск строкой в панели, фильтры и сортировка шитами
- [ ] Поиск в справочнике находит запись, не дожидаясь «Найти»; крестик снимает его
- [ ] Действия строки — по «⋯» с подписями; тап по карточке открывает правку
- [ ] Прайс: пара «мусор · техника» закреплена слева, цены операторов прокручиваются
- [ ] Тап по цене открывает правку; пустая ячейка заводит цену для этой пары и оператора
- [ ] Переименование типа мусора карандашом в закреплённой колонке доступно пальцем

### Руководитель строительства

- [ ] В навигации один раздел — «Заказ ТС»
- [ ] Виза ставится кнопкой прямо в карточке списка и **не открывает** карточку заявки
- [ ] Снятие визы спрашивает подтверждение
- [ ] Журнал «История»: стоимость первой строкой, период работ фильтруется календарём

### Администратор

- [ ] Все четыре раздела в навигации; «Справ.» и «Админ.» подписаны сокращённо
- [ ] Учётки: создание кнопкой в углу, роль и объект выбираются в шите формы
- [ ] Учётки карточками: ФИО с аватаром, роль, email; заявка на регистрацию помечена «Ждёт активации»
- [ ] «Ожидают активации» — пункт шита фильтров, число ожидающих видно в подписи
- [ ] «Рассмотреть заявку», «Отклонить заявку», «Сменить пароль» открываются с карточки
- [ ] Себя деактивировать нельзя — пункт серый, а не пропавший
- [ ] Архивная заявка открывается карточкой; «Восстановить» доступно из меню «⋯»
- [ ] Справочник техники: «Показывать архив» переключателем в шите фильтров

## Поэкранные проверки

### Каркас

- [ ] Нижняя навигация не перекрыта «домашней полоской»; в ландшафте не заезжает под вырез
- [ ] Заголовок раздела в верхней панели совпадает с открытым разделом
- [ ] Меню учётной записи открывается по аватару; «Сменить пароль» и «Выйти» работают
- [ ] Баннер новой версии садится над навигацией и не закрывает её кнопки
- [ ] Семь вкладок справочников прокручиваются; активная видна

### Формы

- [ ] Окно открывается снизу, шапка и кнопки закреплены, скроллится только тело
- [ ] Кнопки «Отмена» и основная делят ширину поровну, не уходят под safe-area
- [ ] Клавиатура не закрывает активное поле
- [ ] **Поворот устройства при открытой форме не стирает введённое**
- [ ] Клик по подложке окно не закрывает

### Списки

- [ ] Карточка читается сверху вниз, ничего не обрезано многоточием без нужды
- [ ] Тап по «⋯» открывает действия и **не открывает** карточку заодно
- [ ] У действий текстовые подписи, недоступные — серые
- [ ] Причина отмены видна текстом (на телефоне подсказок нет)
- [ ] Пустой список говорит «Ничего не найдено», а не выглядит поломкой

### Файлы

- [ ] Список вложений: имя файла не выходит за экран
- [ ] Просмотр фото — во весь экран, изображение целиком
- [ ] PDF открывается фреймом; «Скачать» сохраняет файл

## Регресс десктопа

Проверяется на устройстве **с мышью**. Ожидание: вид не изменился ни на одной ширине.

| Ширина              | Что смотреть                                                                                  |
| ------------------- | --------------------------------------------------------------------------------------------- |
| 1440×900            | боковая панель, полосы фильтров, ширины колонок, модальные окна по центру                     |
| 1280×800            | перенос фильтров, высота тела таблицы, пагинация 100/200/500                                  |
| 600 px (узкое окно) | **мобильный режим не включается**: остаётся боковая панель и горизонтальная прокрутка таблицы |

- [ ] Списки: колонки, сортировка щелчком по заголовку, фильтры в заголовках
- [ ] Формы: модалка по центру, поля парами в строку, календарь с вводом с клавиатуры
- [ ] Карточка заявки: два столбца полей, история таблицей
- [ ] Прайс: отдельные колонки «Тип мусора» и «Техника», переключатель и подсказка в ячейке
- [ ] Факт вывоза: строка в один ряд, количество полем со стрелками

## Принятые компромиссы

Не считать дефектами — это осознанные решения ([ADR 0030](adr/0030-responsive-layout.md),
[ADR 0042](adr/0042-directories-on-phone.md)):

- сводный прайс на 360 px тесен даже с объединённой колонкой: он матрица, и карточкой не
  читается — единственный список, оставшийся таблицей ([ADR 0042](adr/0042-directories-on-phone.md));
- сравнивать записи справочника между собой на телефоне труднее, чем на мониторе: карточка
  показывает одну запись подробно, а не десяток кратко;
- признак «действует» у цены правится в форме, а не переключателем в ячейке;
- мобильный вид не включается на десктопе с мышью при любой ширине окна;
- `capture` у камеры — подсказка браузеру: он вправе открыть выбор файла, и это не ошибка;
- подпись состояния заявки на обслуживание на телефоне некликабельна, хотя на десктопе она ведёт
  в действие: тап по карточке уже открывает карточку, и второй смысл у того же жеста спорил бы с
  первым ([ADR 0125](adr/0125-service-request-cycle-changes.md)).

## Что делать с находкой

1. Записать: роль, устройство, ориентация, экран, что ожидалось и что произошло.
2. Отличить регресс десктопа (правится немедленно) от недоделки мобильного вида.
3. Правку вести в мобильной ветке компонента: десктопная остаётся нетронутой — это правило
   изоляции из ADR 0030, а не пожелание.
