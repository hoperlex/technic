## 3. Решения

**Р1. Метаданные живут в самих ADR, индекс генерируется.** Отдельного YAML/JSON-каталога рядом с
ADR нет: два редактируемых места разойдутся на первой же правке. Единственное исключение —
совместимый реестр доменов для legacy-ADR, в которых этого поля исторически нет; правило `null`
из Р8 запрещает ему стать второй копией после ретрофита. Индекс кладётся в git (а не собирается
на лету), чтобы его читал агент без запуска сборки, а свежесть стережёт `--check` (Р9).

**Р2. 176 существующих ADR не переписываются; разбор у проверки и генератора общий.** Модуль
`scripts/lib/docs-navigation.mjs` читает заголовок и первый блок до первого `##`, склеивает
продолжения строк и нормализует сегодняшние варианты ключей: `Связано` / `Связано с` /
`Связано с кодом`, `Миграция` / `Миграции`, прямые `Изменяет`, `Уточняет`, `Отменяет`, `Заменяет`,
`Развивает`, `Дополняет`, `Расширяет`, `Основано на`, `Реализует`, `Исправляет` и обратные
`Изменён`, `Уточнено <ADR>`. Legacy-разбор допускает пояснение между глаголом и двоеточием —
например, `Отменяет действующую половину:` и `Отменяет — в модуле оргтехники — приём <ADR>:` —
но сохраняет его как уточнение ребра. Для новых ADR действует только точная форма Р3. Остальные
прозаические поля остаются текстом и не получают придуманной семантики.
Генератор и проверка импортируют этот модуль, а не держат по копии регулярных выражений. Обмер
§1.2 показал, что типизированные связи разрешаются уже сегодня; тесты Э1 фиксируют неоднородные
реальные формы до дальнейших правок.

**Р3. Строгий формат — для новых ADR; legacy-шапки остаются совместимыми, и формат остаётся
списком, а не YAML.**
Это отступление от постановки, и вот причина. Frontmatter пришлось бы держать **рядом** с прозаической
шапкой: 176 документов написаны ею, авторы продолжат её писать, а ссылки в ней кликабельны и
проверяемы. Значит появилось бы два места для одного факта — ровно то, что запрещает Р1. Содержание
метаданных берётся из постановки без изменений, меняется только запись:

```markdown
# ADR 0176. Заголовок решения

- Статус: Принято
- Домены: доступ, оргтехника
- Изменяет: [ADR 0021](0021-permissions-model.md) (право — единица доступа)
- Область: [grants.ts](../../packages/contracts/src/grants.ts),
  [mech-requests.ts](../../apps/api/src/routes/mech-requests.ts);
  тесты — [mech-scope.db.test.ts](../../apps/api/test/mech-scope.db.test.ts)
- Миграции: `0261`
```

Обязательны для нового ADR: `Статус`, `Домены`, `Область`; номер заголовка совпадает с именем
файла, ссылки на ADR в полях отношений и пути `Области` записываются относительными
markdown-ссылками. Единственное **новое** поле здесь — `Домены`: остальное уже пишется. Домен не
выводится из текста надёжно (слово «request» встречается в 36 slug-ах), а угаданный домен хуже
отсутствующего — он молча уводит поиск в сторону.

Legacy-ADR можно править точечно без обязательного ретрофита всей шапки: общий разборщик Р2
продолжает понимать старые строки. Новые поля и отношения в нём по правилу для автора пишутся
канонической формой из примера, а уже существующие алиасы не становятся ошибкой. Машинно отличить
новую строку от чужой незавершённой правки в общем рабочем дереве надёжно нельзя; поэтому строгая
проверка сериализации применяется ко всему новому файлу, а для legacy проверяются разрешимость
ссылок и граф; составной `Статус` сохраняется и выводится как написан.

Если машинная строгость важнее дублирования, переключение генератора на frontmatter — правка одного
разборщика; но тогда прозаические шапки надо снимать, а это и есть переписывание 176 документов.

**Р4. Статус не ретрофитится; «действующее против пересмотренного» показывает типизированный
граф.** Семантика рёбер фиксируется явно:

| Поля нового ADR                                                   | Что показывается у старого ADR                    |
| ----------------------------------------------------------------- | ------------------------------------------------- |
| `Отменяет`, `Заменяет`                                            | пересмотр: «отменяет» / «заменяет», с уточнением  |
| `Изменяет`, `Уточняет`, `Исправляет`                              | пересмотр: «изменяет» / «уточняет» / «исправляет» |
| `Развивает`, `Дополняет`, `Расширяет`, `Реализует`, `Основано на` | связанное продолжение, без вывода о статусе       |
| `Связано` / `Связано с`                                           | нейтральная связь                                 |

**Цель ребра опознаётся именем файла, а не номером.** Под 0060 и 0085 живут по два решения, и
ключ-номер выдаёт обоим одинаковый набор связей: «Окончательное удаление записей справочников»
получало пометку «отменён 0142», которая относится к недельному листу ЭСМ-2. Имя файла называет
ссылка в шапке. Голый номер без ссылки у занятого дважды номера цель **не выбирает**: ребро
помечается неоднозначным и показывается как неоднозначность — догадка здесь хуже пропуска, она
молча приписала бы связь не тому решению.

**Уточнение ребра сохраняется.** Отмена бывает частичной, и её границу автор пишет тут же: ADR 0141
отменяет приём ADR 0053 «— **в модуле оргтехники** —», ADR 0145 отменяет «**решение 3** ADR 0133».
Указатель показывает это в скобках после номера. Разбор читает обе живые формы — уточнение до
двоеточия и выделение внутри значения, — потому что первая форма прежнему разбору была вовсе не
видна: имя поля искалось до первого двоеточия и не допускало в себе ни `*`, ни тире, и связь
пропадала целиком.

Обратное поле `Изменён` в старом ADR нормализуется в то же направленное ребро и не дублирует его,
если новый ADR уже содержит прямое поле. Индекс никогда не выводит «изменён» только из факта
входящей нейтральной связи и не объявляет весь старый ADR недействующим по ребру: область отмены
может быть уточнена лишь после перехода в источник. Полную недействительность в индексе означает
только собственный `Статус: Отменено` / `Заменено`. Словарь статуса на будущее — `Принято`,
`Реализовано`, `Отменено`, `Заменено` — обязателен для новых ADR; у legacy составное значение
сохраняется как есть (Р8). Пояснение и дата в новом ADR идут после статуса в отдельном поле или
обычном тексте, а не внутри значения `Статус`.

**Р5. Историю от опечатки отличает история git, а не рукописный baseline.** Отсутствующий путь
проверяется одним вопросом: существовал ли он когда-нибудь в репозитории (`git log --all -- <путь>`).

- **Был и снят** — история. Предупреждение, в индексе пометка «снят». Так и должно быть по §1.3:
  ADR фиксирует решение на момент принятия, и уехавший позже файл в его шапке верен.
- **Не существовал никогда** — опечатка. Ошибка, независимо от возраста ADR.
- **Историю не спросить** — ответ `unknown`, и он не выдаётся за второй. В архиве исходников без
  `.git`, в поверхностном клоне (`--depth`) и при любом сбое `git` двоичный ответ превратил бы
  полсотни исторических путей в ошибки — то есть покрасил бы прогон ровно там, где проверять было
  нечем. `unknown` — предупреждение, под `--strict` — ошибка.

Приём проверен на дереве. Отсутствующих путей в шапках сегодня 27 пар «ADR + путь» на 22
уникальные цели; 21 цель существовала в истории git, а одна —
`apps/api/test/service-request-mail-events.db.test.ts` в шапке
[ADR 0159](adr/0159-service-request-mail-events.md) — не существовал никогда: настоящий файл
называется `service-request-mail.db.test.ts`. Правило «все пути ADR лишь предупреждения» этот дефект
скрыло бы, а рукописный baseline редакции 2 заморозил бы его как «исторический долг».

Главное, ради чего правило переписано: baseline перекладывал расплату на того, кто переименовывает
файл. Он получал красные ворота и обязанность вычитанной правкой дописать причину в чужой ADR.
Частота не гипотетическая — 27 таких путей накопились сами, а FSD-перенос сделан на 7 слайсов из 19.
История git отвечает на тот же вопрос без ручного реестра и без расплаты за чужую работу.

Для `docs/code-map.md` исключений по-прежнему нет (Р10): она описывает сегодня, и снятый путь в ней
— дефект, а не история. Асимметрия намеренна: карта мала и текуща, ADR — 176 исторических записей.

**Р6. Коллизии 0060 и 0085 не перенумеровываются** — решение заказчика. Номер ADR является
историческим идентификатором: 490 ссылок в сообщениях коммитов неизменяемы, а свободен всего один
номер, так что второму 0060 достался бы номер с конца, ломающий хронологию. Вместо перенумерации:
индекс печатает под номером оба документа с различающим заголовком, в шапку каждого из четырёх
идёт строка «Внимание: номер занят и решением …», а проверка (Р7) не даёт **новым** коллизиям
пройти незамеченными. Атомарного резервирования номера в этой работе нет (Р7).

**Р7. Проверяется занятость номера, а не непрерывность нумерации.** Две известные пары вносятся
в исключения как точные множества имён файлов с датой и причиной, а не как разрешённые номера:
третий файл с 0060 или подмена одного из двух имён обязаны стать ошибкой.

Требование редакции 2 «новые ADR образуют непрерывный суффикс после `LEGACY_MAX`» снято. Оно
противоречило принципу Р8 — не ставить зелёный результат в зависимость от чужих файлов, — потому
что непрерывность множества зависит именно от их присутствия в дереве. Сценарий разбирается на
пальцах: параллельный поток берёт 0176, эта работа берёт 0177, пользователь делает `git stash` —
0176 исчезает, проверка краснеет на «0177 не продолжает суффикс», и внутри своей работы это не
чинится. Пропуск в нумерации вредом не является: 0084 пустует с августа и никому не мешает.

Правило «не заполнять освободившиеся номера, брать следующий свободный» остаётся человеческим и
записано в `AGENTS.md`; машина проверяет только коллизию. Номер повторно проверяется
непосредственно перед созданием и после него. Без CI, хука или общей службы резервирования это
детектор, а не атомарная бронь от двух одновременных созданий, поэтому обещание «запрещает завести»
здесь не даётся.

**Р8. Строгость объявляет сам файл, а не снимок дерева.** Строгая форма Р3 спрашивается с ADR,
**в шапке которого есть поле `Домены`**. Есть поле — файл объявил себя написанным по новой форме, и
с него спрашивается всё: словарь статуса, `Область`, канонические markdown-ссылки в отношениях.
Нет поля — tolerant-разбор Р2, домены берутся из реестра §4, а если и там записи нет, ADR попадает
в индекс в раздел «без домена», и проверка считает это предупреждением.

Так снимаются оба дефекта редакции 2. Не нужен ни `LEGACY_MAX`, ни реестр имён, снимаемый на Э0:
темп потока измерен — **23 новых ADR за семь дней, пять за 08.09.2026**, — и любой снимок границы
устаревал бы в тот же день, после чего первый же чужой ADR без нового поля давал бы ошибку в
воротах, которые Э8 делает общими. Признак «есть поле» одинаково работает до коммита, после
коммита, без `origin/main` и в архиве исходников, а новый формат вводится добровольно: пока автор
не написал `Домены`, с него ничего нового не спрашивается.

**Домен спрашивается по состоянию самого файла.** Добровольность поля `Домены` оставляла лазейку:
новое решение могло навсегда остаться вне навигации (риск 7). Поэтому у требования «домен назначен»
две ступени, и обе смотрят только на свой файл:

- решение **ещё не закоммичено** — предупреждение: оно пишется прямо сейчас, и требовать с него
  домен значит красить прогон соседу посреди работы;
- решение **закоммичено** и не имеет ни поля `Домены`, ни строки в реестре §4 — ошибка: оно
  выпадает из указателя, а автор, доведший решение до коммита, знает его домен лучше всех.

Зависимости от чужой работы здесь нет: условие читает git-состояние **того же файла**, а не чей-то
diff и не присутствие чужих файлов в дереве. `git diff` строгость по-прежнему не определяет — в
общем дереве лежат чужие незавершённые правки ADR (§1.5.1), и включение их в «текущую работу»
сделало бы зелёный результат зависимым от чужого файла.

**Р9. Свежесть индекса стережёт `--check`, а сам индекс пишется prettier-стабильным.** Генератор
в режиме `--check` тем же общим модулем Р2 собирает индекс в память и побайтово сравнивает с файлом
на диске; сортировка задаётся явными ключами (домен, числовой номер, имя файла), а не locale
окружения. Расхождение или отсутствие файла — ошибка с подсказкой «запустите `pnpm docs:index`».

Побайтовое сравнение накладывает условие, которого редакция 2 не заметила: `.prettierignore`
покрывает только `dist`, `node_modules`, `coverage`, `pnpm-lock.yaml`, `apps/api/drizzle` и `temp`
— `docs` в нём нет, а `pnpm format` это `prettier --write .`, и markdown-таблицы он выравнивает по
столбцам, маркеры списков нормализует. Без оговорки после любого `pnpm format` `docs:index --check`
краснел бы, а генератор и prettier переписывали бы файл друг за другом. Поэтому **генератор
прогоняет свой вывод через prettier перед записью** (тем же конфигом, `printWidth: 100`), а тест
общего модуля проверяет `prettier(вывод) === вывод`. Вариант «внести индекс в `.prettierignore`»
отвергнут: файл остаётся однородным с остальными `docs`.

Индекс, отставший от ADR, вреднее отсутствующего: он выглядит достоверным.

**Р10. Карта кода перечисляет области и проверяемое владение входами, но не копирует машинные
реестры.** Состав разделов портала читается из
[portal-sections.ts](../packages/contracts/src/portal-sections.ts), матрица прав — ссылкой на
`permissions.ts` и `access-model.md`. В каждом блоке карты явно перечисляются идентификаторы
разделов портала и файлы `apps/api/src/routes/*.ts`, за которые он отвечает; это данные для
проверки полноты, а не второй реестр поведения. Корневые каталоги `apps/api/src/routes/` и
`apps/api/src/` не считаются покрытием всех потомков: иначе одна широкая ссылка дала бы
ложнозелёную карту. Узкий подкаталог можно указать один раз, отдельные файлы плоского каталога —
поимённо. Пути, названные в карте, обязаны существовать (в отличие от вопроса к истории git в Р5): карта описывает
**сегодняшнее** состояние, устаревший путь в ней — дефект, а не история.

**Р11. README правится точечно** — решение заказчика: снимается «Этап 1» и ссылка на
`~/.claude/plans/…` вне репозитория, блок «Структура» приводится к сегодняшнему дереву, добавляются
ссылки на `AGENTS.md`, индекс ADR и карту кода. Матрица прав, режим техработ и безопасность
остаются: они живые и верные.

**Р12. Уровень определяется природой находки, а не этапом.** Принцип один:

> **ошибка — сломано** (ссылка никуда не ведёт, номер задвоен, индекс разошёлся с ADR);
> **предупреждение — не описано** (домен не назначен, маршрут не попал в карту).

Сломанное чинит тот, кто сломал: это следствие его собственной правки. Неописанное ведёт тот, кто
ведёт документацию, и оно не должно ронять чужой прогон. `pnpm check:docs` с первого дня возвращает
ненулевой код на ошибках; `--report-only` печатает те же находки и возвращает 0 — им снимается
базовая линия на Э1. Флаг `--strict` поднимает предупреждения до ошибок: это режим того, кто ведёт
индекс и карту, а не общий.

В `pnpm check` шаг добавляется после нулевого счётчика **ошибок** и роняет прогон только ими
(Э8). Редакция 2 уносила туда же проверки полноты — «маршрут не покрыт картой», «id раздела не
назначен», «`AGENTS.md` длиннее 100 строк», — и тогда новый файл `routes/*.ts` делал бы
`pnpm check` красным, пока кто-то не отредактирует `docs/code-map.md`. Это не прецедент ADR 0147:
линт-долг локален файлу, который автор и так трогает, а здесь была бы обязанность править
отдельный рукописный документ. Счётчик полноты к тому же заново становится ненулевым от обычной
чужой работы — не от долга, а от нормального развития.

**Р13. AGENTS.md один, корневой.** Вложенных в этой работе не заводим. Порог 100 строк остаётся,
но как **предупреждение**: это ограничение длины прозы, и ронять им сборку неправильно. Р13
задумывал порог поводом подрезать справочное содержание, уже доступное по ссылкам в индексе и
карте, — предупреждения для этого достаточно. Отсутствие самого файла — ошибка. Необходимость
правил, специфичных только для `apps/api` или `apps/web`, станет основанием для отдельной задачи
на вложенные файлы, а не скрытым расширением этой работы.

## 4. Домены

Словарь доменов — общий для индекса ADR и карты кода; иначе получатся две несовпадающие
классификации. Предлагается 16, выведенных из разделов портала, маршрутов api и slug-ов ADR:

`вывоз-мусора` · `заказ-тс` · `путевые-листы` · `механизация` · `оргтехника` · `гараж` ·
`кабинет-водителя` · `справочники` · `автозапчасти` · `доступ` · `учётки-и-аудит` · `почта` ·
`файлы-и-распознавание` · `каркас-портала` · `схема-и-выкат` · `качество`

Источник домена у ADR ровно один и определяется самим файлом (Р8): есть поле `Домены` — берётся
поле; нет поля — берётся запись из реестра `имя файла → один или несколько доменов` в общем модуле
Р2. Ключевые слова slug и пути из `Области` используются только при подготовке реестра, не как
эвристика при каждом запуске; результат вычитывается вручную.

Проверка требует, чтобы все значения входили в словарь выше, а домены не приходили одновременно из
поля и из реестра — это единственная настоящая ошибка здесь. Запись реестра, под которую нет файла,
тоже ошибка: реестр не должен переживать свои ADR. А вот ADR без поля и без записи ошибкой не
считается: он попадает в индекс в раздел «без домена», и проверка печатает предупреждение. Иначе
первый же ADR параллельного потока ронял бы общий прогон (Р8, Р12).

Реестр умеет только сокращаться: когда ADR получает поле `Домены`, его запись удаляется. Так у
каждого решения остаётся одно место с фактами, а неявного домена «по совпавшему слову» нет.

## 5. Что кладём в карту кода

На каждую область — один блок неизменной формы:

```markdown
### Доступ

- Текущее состояние: [access-model.md](access-model.md)
- Источник истины: [permissions.ts](../packages/contracts/src/permissions.ts) (матрица),
  [permission-catalog.ts](../packages/contracts/src/permission-catalog.ts),
  [grants.ts](../packages/contracts/src/grants.ts),
  [grant-scope.ts](../packages/contracts/src/grant-scope.ts)
- Разделы портала: `—`
- API-маршруты: [auth.ts](../apps/api/src/routes/auth.ts),
  [grants.ts](../apps/api/src/routes/grants.ts)
- Остальной API: [auth](../apps/api/src/auth/), [access.ts](../apps/api/src/lib/access.ts)
- Web: [auth](../apps/web/src/auth/)
- Тесты: `access-matrix`, `route-authorization`, `grants-contracts`, `permissions-ui`
- Решения: [ADR 0021](adr/0021-permissions-model.md),
  [ADR 0038](adr/0038-executor-permissions-by-counterparty-type.md),
  [ADR 0106](adr/0106-assignable-permission-grants.md)
```

Обязательные строки каждого блока — `Источник истины`, `Разделы портала`, `API-маршруты` и
`Решения`; отсутствие применимого значения записывается явным `—`. В `Разделы портала` идут
точные `id` из реестра, причём каждый id имеет ровно один основной продуктовый блок. В
`API-маршруты` — ссылки на файлы или узкие подкаталоги по правилу Р10; один маршрут может
принадлежать нескольким областям, но не может не принадлежать ни одной. Остальные пути тоже
оформляются markdown-ссылками, чтобы их проверял общий механизм, а не особый grep по обратным
кавычкам.

Сквозные механизмы (доступ, аудит, файлы/S3, почта, транзакции, миграции и выкат, ошибки,
фоновые задачи) описываются такими же блоками, без отдельного формата. Они могут ссылаться на
продуктовые области и повторно владеть API-маршрутом, но не забирают у продуктового блока его
идентификатор раздела портала.

`pnpm check` роняется только ошибками. `check:docs --strict` поднимает предупреждения до ошибок —
режим того, кто ведёт индекс и карту. Рукописного baseline отсутствующих целей нет: его заменил
вопрос к истории git (Р5). Сводка показывает счётчики markdown-ссылок и путей шапок отдельно, даже
если одна ссылка попала в обе проверки; диагностическая строка для одной позиции печатается один
раз. Новая битая ссылка никогда не становится предупреждением только потому, что похожа на путь к
коду: решает история git, а не форма строки.

Ссылки проверяются в `README.md`, `AGENTS.md` и `docs/**/*.md`. Разбор пропускает огороженные
блоки кода, внешние схемы (`https:`, `mailto:` и другие), чистые `#anchor` и корневые URL портала
вида `/login`. Для inline- и reference-style Markdown ссылок и изображений он снимает
query/fragment, декодирует percent-encoding и разрешает путь от каталога исходного документа;
выход за корень репозитория — ошибка. Якоря внутри существующего файла в эту работу не входят.

**Inline code пропускается при поиске markdown-ссылок, но не при разборе шапки ADR.** Это не
частность: **786 из 957 путей в шапках (82%) написаны обратными кавычками, и там же лежат все 27
отсутствующих**. Правило редакции 2 «разбор пропускает fenced code и inline code» целиком обнулило
бы проверку путей ADR — она молча проходила бы с нулём находок. Поэтому у разбора два входа:
markdown-ссылки берутся из текста без кода, пути шапки — из текста вместе с inline code. Огороженные
блоки не читает ни один: примеры в планах и в этом файле пишут пути относительно того каталога, о
котором рассказывают. Проверено на самом плане — наивный обход находит в §3 четыре несуществующие
цели, которых там нет.

Подсказка исправления ADR даётся только при единственном файле с таким номером; для 0060/0085
неоднозначность выводится без автоисправления.

Форма вывода — как у `scripts/check.mjs`: прогон не останавливается на первой находке, итог
собирается таблицей в конце, числа печатаются всегда. Приём разбора — как у
`apps/web/scripts/check-portal-routes.mjs`: реестр контрактов читается разбором файла, а не
импортом (модули контрактов пишут импорты без расширений, голым Node такой файл не грузится).
Тесты общего модуля покрывают многострочную шапку, алиасы полей, направление и дедупликацию рёбер,
две известные коллизии плюс третий файл, все исключения ссылок выше, уникальную и неоднозначную
подсказку ADR. Отдельные проверки на реальном дереве фиксируют полноту legacy-доменов,
идемпотентность индекса и полноту карты; числа файлов при этом вычисляются, а не зашиваются.

## 7. Этапы

**Э0. Повторяемый обмер по закоммиченному состоянию.** Первый снимок дан в §1, пересчёт
редакции 3 — в §1.5.1; непосредственно перед реализацией теми же правилами пересчитываются ADR,
документы, маршруты и ссылки. Обмер берётся **только с закоммиченного дерева** (`git stash list`
проверяется, рабочие правки не учитываются): в дереве прямо сейчас лежат 17 чужих незавершённых
правок ADR, и снимок по ним закрепил бы чужой промежуточный результат, который `git stash` унесёт.
Ни `LEGACY_MAX`, ни реестр имён ADR больше не фиксируются — строгость объявляет сам файл (Р8);
единственное, что готовится разово, — реестр доменов §4.
_Готово, когда:_ расхождения со снимком объяснены новыми и удалёнными файлами, а не ошибкой
выборки, и ни одно число не стало константой кода.

**Э1. Общий разборщик, его тесты и `scripts/check-docs.mjs`.** Сначала фиксируются тестами реальные
формы шапок и ссылок из Р2 и §6, затем поверх общего модуля делаются коллизии, классы ссылок,
вопрос к истории git, граф и строгие поля ADR с полем `Домены`. В `package.json` появляются
`check:docs` и `test:docs`; в `pnpm check` команда пока не включается. Обычный запуск уже честно
падает на ошибках, а первичный отчёт снимается флагом `--report-only` (Р12).
_Готово, когда:_ `pnpm test:docs` зелёный, report-only воспроизводит классы §1.5 и 0 новых
коллизий, а тот же прогон без флага возвращает ненулевой код.

**Э2. Остаток ручной чистки ссылок.** Механические классы закрыты параллельным потоком (§1.5.1):
`../` и неверных slug-ов сегодня ноль. Остаётся то, что машина чинить не должна: 25 ссылок и 27
путей шапок, снятых историей git, — они остаются предупреждениями по Р5 и не правятся вовсе; и
единственная настоящая ошибка — `apps/api/test/service-request-mail-events.db.test.ts` в шапке
[ADR 0159](adr/0159-service-request-mail-events.md), пути с таким именем никогда не было, настоящий
файл называется `service-request-mail.db.test.ts`.
Если к моменту этапа механические классы снова окажутся ненулевыми, они правятся скриптом с ручной
вычиткой диффа — проверка их узнаёт независимо от того, кто их завёл.
_Готово, когда:_ `check:docs` возвращает ноль ошибок, а предупреждения объяснены историей git.

**Э3. Точная legacy-классификация и генератор индекса.**
`scripts/gen-adr-index.mjs` → `docs/adr/README.md`; режимы записи и `--check`. Эвристика помогает
подготовить точный реестр по текущим legacy-файлам (§4), после чего при запуске ничего не
угадывается.
Строка ADR в индексе: ссылка на файл, номер, заголовок, статус, домены, семантически названные
обратные рёбра Р4, миграции и **все** пути, названные в поле `Область`, в порядке появления.
Лимита «до пяти путей» нет: из 160 ADR, назвавших путь, у 75 (46%) их больше пяти, и лимит обрывал
бы ответ на «где это в коде» почти у половины решений — ровно там, ради чего индекс и открывают.
Медиана 4–5, хвост редкий: полный список дешевле счётчика остатка.

Поле `Область` разбирается **отдельно от остальной шапки**, но есть оно лишь у 54 решений из 177.
У остальных ту же роль играет legacy-написание: область названа прямо в «Связано» (так писан ADR
0021 и вся ранняя половина корпуса). Поэтому при отсутствии поля указатель берёт пути из шапки
целиком — это не запасной ход, а тот же факт в прежнем правописании, ровно как с синонимами полей
в Р2. Проверке же нужны **все** пути шапки в любом случае: опечатка в любом поле остаётся опечаткой. ADR без источника
доменов попадает в раздел «без домена» (Р8, §4). Один ADR с несколькими доменами виден в каждом из
них, а итог в шапке считает уникальные файлы. Перед записью вывод прогоняется через prettier (Р9).
_Готово, когда:_ каждый текущий ADR имеет ровно один источник доменов, все рёбра разрешены либо
явно неоднозначны из-за 0060/0085, индекс собран, `--check` зелёный и повторный запуск не меняет
файл.

**Э4. Пометки о коллизиях** в шапках четырёх ADR (Р6) и точные пары исключений в проверке (Р7).
После правки индекс пересобирается и снова проходит `--check`.

**Э5. `docs/code-map.md`.** Области по форме §5 пишутся по индексу Э3, `app.ts` и реестру
`portal-sections.ts`. Самый дорогой этап по чтению: ≈16 областей × сверка слоёв. Проверка каждый
раз получает фактический список разделов и файлов маршрутов из дерева: нынешние 8 разделов
общего каркаса плюс кабинет водителя и 57 маршрутов — снимок, а не константа.
_Готово, когда:_ каждый фактический id реестра назначен ровно одному продуктовому блоку, каждый
фактический `routes/*.ts` покрыт хотя бы одним блоком, широких корневых покрытий нет и все пути
карты существуют.

**Э6. `AGENTS.md`.** Иерархия источников истины (код → `access-model.md`/`database-schema.md` →
ADR → планы), команды (`pnpm check`, `check:db`, `check:docs`, `db:migrate`), правила про номера
ADR и миграций, ссылки на индекс и карту. Добавляются `docs:index`, `check:docs` и `test:docs`,
объяснение границы legacy Р8 и оговорка Р7 о неатомарной выдаче номера. Порог 100 строк — Р13.

**Э7. README** точечно (Р11).

**Э8. Фиксация решения и включение в ворота.** После Э2–Э7 снова вычисляется следующий свободный
номер (`0176`, если параллельный поток его не занял), непосредственно до и после создания
проверяются коллизии, создаётся ADR и обновляется ссылка в этом плане. Затем индекс пересобирается.
`check-docs` добавляется отдельным шагом в `scripts/check.mjs`: как и остальные шаги, он не
останавливает запуск последующих, но участвует в финальном коде возврата **ошибками, а не
предупреждениями** (Р12). Проверки полноты — покрытие карты, назначение id раздела, длина
`AGENTS.md` — остаются предупреждениями и в общих воротах не краснеют; их поднимает `--strict` у
того, кто ведёт документацию.
_Готово, когда:_ зелёные `pnpm test:docs`, `pnpm docs:index --check`, `pnpm check:docs` и полный
`pnpm check`; `git diff --check` чист, а повторная генерация индекса ничего не меняет.

Зависимости: Э1→Э2; Э1→Э3→Э4; Э3→Э5→Э6; Э7 можно выполнять после Э1 параллельно с Э2–Э6;
Э8 начинается только после Э2, Э4, Э5, Э6 и Э7. Это устраняет прежнее противоречие, где Э5
назывался независимым от Э3, хотя строился по его индексу.

## 8. Чего в работе нет

- Ручного индекса файлов и символов: он дешевле добывается `rg` и языковым сервером.
- Отдельного JSON/YAML-каталога рядом с ADR (Р1).
- Массовой простановки ссылок на ADR в коде: их уже 490, и нужны они у инвариантов, а не у каждой
  функции.
- Vector DB и RAG: для 3 МБ структурированного Markdown с тегами это преждевременно.
- Вложенных `AGENTS.md` (Р13) и переписывания 176 ADR (Р2).
- Перенумерации коллизий (Р6).
- CI: его в репозитории нет вовсе, и заводить его этой работой не следует — ворота остаются
  ручной командой, как решено ADR 0147.

## 9. Риски

**Р-риск 1. Индекс отстанет.** Закрыт `--check` (Р9) и шагом ворот (Э8). До Э8 автоматического
вызова из общих ворот нет, поэтому каждый этап, меняющий ADR, явно заканчивается пересборкой и
проверкой индекса.

**Р-риск 2. Карта кода отстанет** — она пишется руками. Частично закрыто проверками путей и
покрытия разделов (§6), полностью — нет: перечисленные пути могут существовать и при этом
описывать вчерашний сценарий. Смягчение: карта называет источники истины ссылкой, а не копией
(Р10), и автоматически сторожит точки входа. Семантическое устаревание описания полностью
автоматикой не закрывается и остаётся ценой ручной карты.

**Р-риск 3. Общее рабочее дерево.** Он уже сработал: параллельный поток за время написания плана
поправил 17 ADR и закрыл механическую часть Э2 (§1.5.1), а правки не закоммичены и могут уехать в
`git stash`. Отсюда правила работы: обмер и базовая линия — только по закоммиченному состоянию
(Э0), коммитить строго явными путями, свои хвосты в общих файлах вести списком. Проверки
намеренно не смотрят ни в `git diff`, ни в присутствие чужих новых файлов (Р7, Р8) — иначе чужая
незавершённая правка красила бы свой прогон.

**Р-риск 4. Домены окажутся не теми.** Словарь §4 выведен из slug-ов и разделов портала.
Смягчение: эвристика только предлагает первичный точный реестр, человек вычитывает его по 176
файлам, а проверка запрещает пропуски, неизвестные значения и два одновременных источника.

**Р-риск 5. Реестр доменов сам станет вторым каталогом.** Он нужен только как адаптер старых ADR
и умеет лишь сокращаться: получил ADR поле `Домены` — запись удаляется (§4). Одновременные два
источника и запись без файла — ошибки. Заголовки, статусы, связи, пути и миграции в реестр не
копируются.

**Р-риск 6. Два потока одновременно выберут один номер ADR.** Повторная проверка до и после
создания сужает окно, но не делает операцию атомарной (Р7). При обнаружении новой коллизии Э8 не
завершается: ещё не опубликованный файл получает следующий свободный номер до появления ссылок на
него. Темп потока — 23 ADR за семь дней — делает это не теорией, а ожидаемым событием.

**Р-риск 7. Новый формат ADR не приживётся.** Р8 сделал его добровольным: пока автор не написал
`Домены`, с него ничего не спрашивается, и ADR попадает в индекс без домена. Это осознанный размен
— общий прогон не краснеет от чужой обычной работы, но и переход не наступит сам. Сигналом служит
счётчик предупреждений «без домена» в сводке: если он не убывает, вопрос выносится отдельно, а не
закрывается ужесточением проверки задним числом.
**Р-риск 6. Два потока одновременно выберут один номер ADR.** Повторная проверка до и после
создания сужает окно, но не делает операцию атомарной (Р7). При обнаружении новой коллизии Э8 не
завершается; один ещё не опубликованный файл получает новый следующий номер до появления ссылок
на него.
