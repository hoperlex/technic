# План: крупный шрифт на странице передачи показаний

Рабочий план, не ADR. Продолжение [driver-cabinet-ux-plan.md](driver-cabinet-ux-plan.md) (Р1,
«крупный шрифт») и [driver-readings-first-plan.md](driver-readings-first-plan.md): кабинет
открывается формой показаний (ADR 0129, коммит `766bcb3`), и правка касается ровно её — index-роут
`/driver`. Решения помечены **Р**, развилки — **У**; нумерация своя.

Постановка: «шрифты крупнее, в первую очередь дата в шапке (слайдер со стрелками) и госномер
машины с подписями строк показаний».

**Состояние: реализовано 21.08.2026**, выпуск `0.1.36.0129` (миграция `0173`, записью журнала —
схема не тронута). Развилки закрыты заказчиком: **У1 — зашитая величина**, **У2 — 1.25**.

---

## 1. Что стоит на экране сегодня

Масштаб кабинета уже есть — одна переменная на каркасе
([readingLimits.ts](../apps/web/src/pages/driver/readingLimits.ts), `DRIVER_FONT_SCALE = 1.15`,
и правило `.driver-shell { font-size: calc(16px * var(--driver-scale)) }`). Экран всё равно мелкий,
и причин три — каждая своя, одной правкой размера не лечится ни одна.

**Причина 1. Масштаб не доходит до antd.** `.ant-typography` размера не задаёт вовсе и наследует
каркас — поэтому голый текст в кабинете и правда 18,4 px. А `Input`, `Button`, `DatePicker`,
`Alert`, `Checkbox` берут размер из **токена темы**, а не от родителя: мобильная тема портала
(`themeFor(true)`) даёт им `fontSize: 16`, десктопная — 14. Получается вывернутая картина: то, что
человек **читает**, крупнее того, что он **набирает**. Число одометра — единственное место, где
ошибка стоит денег, — набирается шрифтом мельче окружающего текста.

**Причина 2. Иерархия блока перевёрнута.** В шапке блока строки сегодня стоят:

```
Рейс Р-142            ← Typography strong, 18,4 px, чёрный
А123ВС799             ← Typography secondary, 0.85em = 15,6 px, серый
```

Госномер — самый мелкий и самый бледный элемент блока, хотя это единственный признак, по которому
водитель сверяет строку с машиной во дворе. (Подпись в отчёте — это именно госномер: сервер
собирает её общим правилом `vehicleLabel` — [readings.ts:1973](../apps/api/src/services/readings.ts#L1973),
у своей техники это `registrationNumber`, у аренды — описание.)

**Причина 3. Мелкие подписи считаются от базы, которая сама не выросла.** `0.85em` в четырёх
файлах кабинета — подписи полей («Одометр на конец смены»), подсказка «предыдущее: 145 320 (10.08)»,
подпись состояния дня, поля блока «введено, но не привязано».

Замер (мобильная тема, `DRIVER_FONT_SCALE = 1.15`):

| Элемент страницы                    | Сейчас               | Откуда берётся                 |
| ----------------------------------- | -------------------- | ------------------------------ |
| Дата в шапке («Сегодня, 21 авг»)    | 16 px, обычный       | токен `fontSize` темы          |
| Стрелки дня                         | кнопка 40, значок 16 | `controlHeight` темы           |
| Заголовок «Показания за 21 августа» | 18 px                | `fontSizeHeading5`             |
| Состояние дня («Черновик»)          | 18,4 px              | каркас                         |
| **Госномер машины**                 | **15,6 px, серый**   | `0.85em` + `secondary`         |
| Номер рейса / ЭСМ-2                 | 18,4 px, чёрный      | каркас                         |
| **Подпись поля («Одометр…»)**       | **15,6 px, серый**   | `0.85em` + `secondary`         |
| **Число в поле ввода**              | **18 px**            | `fontSizeLG` темы              |
| «предыдущее: 145 320 (10.08)»       | 15,6 px, серый       | `0.85em`                       |
| Кнопка «Передать»                   | 18 px, высота 50     | `fontSizeLG`/`controlHeightLG` |

## 2. Р1. Масштаб доходит до antd: у кабинета своя тема

Одна константа остаётся одной константой, но теперь из неё считается **и** переменная CSS, **и**
тема antd. Иначе правка масштаба и дальше будет двигать только половину экрана.

Новый модуль `apps/web/src/pages/driver/theme.ts`:

```ts
export const DRIVER_BASE_FONT_PX = 16; // база портала, от неё считается всё
export const DRIVER_FONT_SCALE = 1.25; // было 1.15
export const DRIVER_NUMBER_SCALE = 1.4; // числовые поля — отдельно и крупнее (Р4)
export const DRIVER_CONTROL_HEIGHT = 48; // тач-цель управляющих элементов

export function driverTheme(): ThemeConfig; // token + components, собирается один раз
```

Токенов ровно два — `fontSize: 20` (16 × 1.25) и `controlHeight: 48`; остальное antd выводит сам
(`fontSizeSM 16`, `fontSizeLG 24`, `fontSizeHeading5 24`, `lineHeight 1.4`, `controlHeightLG 60`,
`controlHeightSM 36`). Перечислять производные руками значило бы завести десяток чисел, которые
разъедутся с первой же правкой базы.

Третий токен — компонентный, и он вынужденный: ячейка календаря считается как
`controlHeightSM × 1.5` (правило самого antd, `date-picker/style/token.js`), то есть 54 px, а панель из семи ячеек — ~394 px и не влезает в телефон 360. Поэтому
`components: { DatePicker: { cellWidth: 44, cellHeight: 40 } }` — панель ~340 px.

Тема подключается **в каркасе кабинета** ([DriverLayout.tsx](../apps/web/src/pages/driver/DriverLayout.tsx)),
а не на странице показаний: у кабинета две страницы одного дня, и разъехаться им размером нельзя.
Вместе с `ConfigProvider` внутрь кабинета ставится и вложенный `<App>` antd: `message.error(...)`
страница показаний берёт из ближайшего контекста, и без вложенного `App` тосты остались бы
портальными 16 px там, где всё вокруг 20.

Тема не ветвится по `useIsMobile` намеренно: кабинет открывают и с планшета в кабине, и это тот же
человек в тех же условиях. Ветвление дало бы ему на планшете портальные 14 px.

Переменная каркаса остаётся и считается от тех же констант:

```css
.driver-shell {
  font-size: calc(16px * var(--driver-scale, 1)); /* 20 px */
}
```

## 3. Р2. Дата в шапке

Три правки, все в [DriverLayout.tsx](../apps/web/src/pages/driver/DriverLayout.tsx) и `styles.css`:

1. **Сама подпись — крупная и полужирная.** `1.15em` от базы кабинета — 23 px, `font-weight: 600`.
   Стиль идёт классом `.driver-date`, а не инлайном: размер задаёт внутренний `input` пикера,
   до которого `style` на компоненте не доходит.
2. **Ширина — гибкая, а не 168 px.** `flex: 1 1 auto`, `min-width: 0`, текст по центру. Фиксированная
   ширина при 23 px обрежет «Сегодня, 21 авг».
3. **Год уходит из подписи.** Окно чтения — ±дни от сегодня (`DRIVER_ASSIGNMENT_PAST_DAYS`,
   `DRIVER_ASSIGNMENT_FUTURE_DAYS`), и год в нём не различает ничего, а места занимает больше всех:

   | Дата       | Было              | Станет       |
   | ---------- | ----------------- | ------------ |
   | сегодня    | `Сегодня, 21 авг` | `Сегодня`    |
   | вчера      | `Вчера, 20 авг`   | `Вчера`      |
   | прочие дни | `чт, 21 авг 2026` | `вт, 19 авг` |

   «Сегодня» без числа — не потеря: число этого же дня стоит заголовком над формой («Показания за
   21 августа»), крупным шрифтом и в двух шагах ниже.

**Стрелки** становятся тач-целью 48 × 48 (`controlHeight` темы даёт её сам), значок — 22 px
(`fontSize: '1.1em'` на иконке). Отдельно проверяется, что «Предыдущий день» и «Следующий день»
остаются `aria-label` теми же: по ним ходят тесты кабинета.

Бюджет ширины на телефоне 360 после правки: логотип 44 + стрелки 96 + аватар 44 + зазоры 12 = 196;
дате остаётся ~148 px при нужных ~110. Влезает с запасом, а «вт, 19 авг» — самая длинная из подписей.

## 4. Р3. Госномер — первым и крупным

Шапка блока в [DriverReadingBlock.tsx](../apps/web/src/pages/driver/DriverReadingBlock.tsx)
переворачивается:

```
А123ВС799             ← 1.2em (24 px), font-weight 600, чёрный
Рейс Р-142            ← 0.9em (18 px), secondary
```

Госномер — то, чем водитель узнаёт строку; рейс — то, чем он различает две строки одной машины за
день (две смены). Сначала опознание, потом различение.

Сервер не трогается: подпись уже приходит госномером (`vehicleLabel`), и парсить строку «марка ·
госномер» — как в задании — здесь не нужно и нельзя (у аренды госномера нет вовсе, там описание,
ADR 0018).

## 5. Р4. Подписи полей и сами числа

В том же файле:

- **Подпись поля** («Одометр на конец смены», «Моточасы на конец смены», «Заправлено за смену»,
  «Комментарий») — `1em` (20 px) и **обычным цветом**, без `type="secondary"`. Это заголовок поля,
  а не примечание к нему: серым 15,6 px он читается как подпись под чужим полем.
- **Число в поле** — своя переменная, `calc(16px * var(--driver-scale) * var(--driver-number-scale))`
  = 28 px, `font-weight: 600`, `font-variant-numeric: tabular-nums` (цифры одной ширины — набранное
  не «прыгает» при вводе). Правило вешается классом `.driver-number` на числовые поля; комментарий
  остаётся базовым — его не сверяют с прибором.
  Это ровно то, что план кабинета обещал в Р1 («числовые поля отдельно и крупнее, 1.35») и что до
  кода тогда не доехало.
- **Подсказка «предыдущее: 145 320 (10.08)»** — `0.9em` (18 px), остаётся `secondary`: она рядом с
  тем, с чем сверяют, и перебивать собой набранное не должна.
- **Ошибка поля** — `0.9em`, `danger` (было `0.85em`).

## 6. Р5. Подвал и резерв высоты под ним

Кнопка «Передать» с новой темой — высотой 60 (`controlHeightLG`), шрифт 24. Значит резерв под
закреплённым подвалом на странице показаний
([DriverReadingsPage.tsx](../apps/web/src/pages/driver/DriverReadingsPage.tsx),
`contentStyle: { paddingBottom: 72 }`) перестаёт хватать: 60 + отступы 16 = 76 плюс `safe-bottom`.
Число уезжает константой `DRIVER_FOOTER_RESERVE = 96` в модуль темы — рядом с высотой элемента, из
которой оно и считается. 72 px, оставленные на месте, дали бы кнопку поверх последнего поля — то
есть ровно то, от чего подвал и закрепляли (Р9 плана первого экрана).

## 7. Р6. Остальные подписи кабинета — той же рукой

Чтобы экран не остался разноразмерным лоскутом:

| Место                                        | Было      | Станет                    |
| -------------------------------------------- | --------- | ------------------------- |
| Строка состояния дня (`DayLine`, «Черновик») | 18,4 px   | 1.1em (22 px), полужирный |
| Подсказка под ней («Можно поправить…»)       | `0.85em`  | `0.9em`                   |
| Ссылка «Задание» в шапке (`.driver-nav`)     | `0.95em`  | `1em`                     |
| Строка долга (`.driver-pending`)             | `0.9em`   | `0.95em`                  |
| Поля блока «введено, но не привязано»        | `0.85em`  | `0.9em`                   |
| Пометка «Введено, но не передано»            | наследует | наследует (Alert темы)    |

Заголовок «Показания за 21 августа» отдельной правки не требует: с темой кабинета
`fontSizeHeading5` = 24 px, то есть заголовок наконец крупнее текста под ним.

## 8. Границы правки

Не делается — намеренно:

- **сервер и контракты не трогаются вовсе**: ни одного нового поля, ни одной новой подписи;
- **композиция страницы не меняется**: те же блоки, тот же порядок, тот же подвал. Правка про
  размер и вес, а не про устройство экрана;
- **страница задания** (`/driver/assignment`) получает только общий масштаб темы — её собственную
  вёрстку не пересматриваем;
- **признак смены** («смена 2» у второй строки той же машины за день) в шапку блока не добавляется:
  это новая подпись, а не размер существующей;
- **портал вне кабинета** не задевается ничем: тема живёт внутри `DriverLayout`.

## 9. Развилки (закрыты 21.08.2026)

**У1. Один зашитый масштаб или переключатель размера в кабинете? → зашитый.**
Предлагается **зашитый** (`DRIVER_FONT_SCALE`), подбираемый на живом телефоне одним числом.
Переключатель «А/А» — это ещё одно состояние на человека, хранимое в `localStorage` того же
телефона, который в бригаде бывает общим; водитель, получивший чужой мелкий шрифт, окажется ровно
там, откуда начали. Если переключатель всё же нужен — это отдельная работа, и делать её надо после
того, как базовая величина устоялась.

**У2. Насколько крупно — 1.25 или больше? → 1.25.**
Предлагается **1.25** (база 20 px, числа 28 px, госномер 24 px). Дальше начинается плата высотой:
при 1.4 шапка кабинета (логотип-строка + «Задание» + строка долга) съедает ~180 px из 640 у
телефона 360 × 640, и на форму остаётся меньше двух блоков. Проверяется это на живом телефоне за
один прогон: обе величины — одно число в одном файле.

Читающий день (принятый, аннулированный, старше семи суток) выглядит так же, но поля выключены, а

1. дата в шапке — 16 → **23 px, полужирная**, без года, шире; стрелки 40 → **48**;
2. госномер — 15,6 px серый **под** рейсом → **24 px полужирный над ним**;
3. подписи полей — 15,6 px серые → **20 px чёрные**;
4. набираемые числа — 18 → **28 px полужирные**, цифры одной ширины;
5. подсказка «предыдущее» — 15,6 → **18 px**;
6. заголовок дня — 18 → **24 px** (крупнее текста, а не вровень с ним);
7. кнопка «Передать» — 18 px / 50 → **24 px / 60**, резерв под подвалом 72 → 96;
8. всё прочее в кабинете (тосты, `Alert`, чекбокс подтверждения, календарь) выросло вместе с темой.

## 12. Чем проверяется

- **Существующий тест на горизонтальную прокрутку** (`driver-cabinet.test.tsx`, `document.body.scrollWidth
<= window.innerWidth`) — главная страховка правки: крупный шрифт ломает верстку вбок первым.
- **Новый тест на подпись даты**: «Сегодня» и «Вчера» без числа, прочие дни — без года.
- **Новый тест на то, что кабинет крупнее портала не только текстом**: токены темы кабинета
  сравниваются с портальной мобильной темой, а правила `.driver-date` и `.driver-number`
  проверяются в самой таблице стилей — до внутренних полей ввода antd инлайновый стиль не доходит,
  и «упростить» их обратно тест не даст.
- **Существующие тесты кабинета** (`driver-readings`, `driver-readonly`, `driver-open-protocol`,
  `driver-day-matrix`) обязаны пройти без правок: тексты и `aria-label` не меняются, меняются
  размеры. Если какой-то падает — это сигнал, что правка задела не только размер.
- **На живом телефоне** (360 × 640 и iPhone SE): дата не обрезана, календарь влезает по ширине,
  кнопка «Передать» не накрывает последнее поле, при открытой клавиатуре подвал над ней.

## 13. Выкат

Схема не тронута; в журнал обновлений ушла запись выпуска миграцией
`0173_releases_driver_typography.sql` — `seq` 43, версия `0.1.36.0129`. Хвост версии по ADR 0129:
своего решения у правки нет, она доводит до конца тот самый кабинет, который этим ADR и открыт
формой показаний. ADR не заводился — архитектурного решения здесь нет, есть подбор величин;
величины и обоснования живут в этом плане.

Выкат обычный, одним куском: сервер не задет, миграция только вставляет строку журнала. Обратный
ход — тем же способом, что у прочих записей выпуска.
